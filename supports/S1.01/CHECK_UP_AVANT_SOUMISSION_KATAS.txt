--------------------------------------------------------------------------------
 [PHASE 1] AVANT DE COMMENCER À CODER (Analyse au brouillon)
--------------------------------------------------------------------------------
 [ ] 1.1 Lire attentivement l'énoncé et identifier :
         - Les données en entrée (saisie clavier ? tableau déjà rempli ?)
         - Les résultats attendus en sortie (affichage écran ? calcul ?)
         - Les contraintes (bornes, valeurs d'arrêt, cas limites).
 [ ] 1.2 Identifier le MODÈLE D'ALGORITHME officiel adapté au problème :
         - Modèle 1 : Échange de deux valeurs
         - Modèle 2 : Saisie-vérification d'une valeur
         - Modèle 3 : Parcours complet avec traitement systématique
         - Modèle 4 : Parcours complet avec traitement conditionné
         - Modèle 5 : Recherche de première occurrence
         - Modèle 6 : Recherche d'extremum (Min / Max)
 [ ] 1.3 Remplir le CARTOUCHE OBLIGATOIRE au tout début de 'main.cpp'.
         ATTENTION : Un fichier rendu sans cartouche = 0/20 direct !
         (Voir modèle de cartouche en Section 3 ci-dessous).

--------------------------------------------------------------------------------
 [PHASE 2] DÉCLARATION & TYPAGE STRICT (Norme R1.01)
--------------------------------------------------------------------------------
 [ ] 2.1 Zéro nombre magique dans le code :
         Toute valeur fixe (taille de tableau, borne min/max, valeur d'arrêt,
         taux de TVA) DOIT être déclarée sous '// CONSTANTES' en majuscules :
         Exemple : const unsigned short int TAILLE_MAX = 50;
                   const short int TEMP_MIN = -30;
                   const unsigned short int VALEUR_ARRET = 999;
 [ ] 2.2 Typage au plus juste (Précision du typage - Coeff 2) :
         - Tailles de tableaux, indices, âges, effectifs, compteurs positifs :
           -> Utiliser 'unsigned short int' (si < 65 535) ou 'unsigned int'.
              NE PAS mettre bêtement 'int' partout !
         - Entiers relatifs (températures négatives, coordonnées relatives) :
           -> 'short int' ou 'int'.
         - Moyennes, pourcentages, prix réels :
           -> 'float' ou 'double'.
         - Drapeaux et conditions d'état :
           -> 'bool' (ex: bool trouve = false; bool saisieValide = true;).
 [ ] 2.3 Conventions de nommage respectées (Coeff 2) :
         - CONSTANTES  : MAJUSCULES_SOULIGNEES (ex: VAL_ARRET, EFFECTIF_S1)
         - Variables   : lowerCamelCase signifiant (ex: sommeNotes, noteValide)
         - Structures  : UpperCamelCase (ex: struct Etudiant)
         - INTERDIT : variables à une seule lettre (x, y, a, b, temp, truc)
           sauf les variables d'indices de boucle (i, j).
 [ ] 2.4 Chaque variable déclarée possède son commentaire explicatif à droite :
         Exemple :
         float moyenne; // Moyenne calculée des notes valides saisies
         unsigned short int nbNotes; // Nombre de notes valides comptabilisées

--------------------------------------------------------------------------------
 [PHASE 3] ARCHITECTURE DU CODE & TRIPARTITION CANONIQUE
--------------------------------------------------------------------------------
 [ ] 3.1 La structure de 'int main(void)' respecte scrupuleusement les 3 blocs :
         int main(void)
         {
             // CONSTANTES
             ...
             // VARIABLES
             ...
             // TRAITEMENTS
             ...
             return 0;
         }
 [ ] 3.2 Chaque bloc d'action dans '// TRAITEMENTS' a son commentaire de flot
         de données au format Patrick Etcheverry (données >> action >> résultats) :
         Exemples :
         // (clavier) >> Saisir-vérifier la température >> temperature
         // tabNotes, EFFECTIF >> Calculer la moyenne >> moyenne, nbNotesValides
         // moyenne >> Afficher le résultat >> (écran)

--------------------------------------------------------------------------------
 [PHASE 4] RESPECT STRICT DES MODÈLES & STRUCTURES DE CONTRÔLE (Coeff 16/30 !)
--------------------------------------------------------------------------------
 [ ] 4.1 La boucle utilisée correspond exactement à la situation :
         - Nombre de tours CONNU d'avance -> Boucle 'for' :
           for (i = 0; i < TAILLE; i++)
         - Saisie-vérification (au moins une saisie, arrêt si valide) -> 'for(;;)' :
           for ( ; ; )
           {
               cout << "Saisir valeur : ";
               cin >> val;
               if (val >= MIN && val <= MAX) break;
               cout << "Erreur, valeur hors bornes !" << endl;
           }
         - Recherche de première occurrence (parcours partiel avec arrêt) -> 'while' :
           trouve = false;
           i = 0;
           while (!trouve && (i < TAILLE))
           {
               if (tab[i] == cible) trouve = true;
               else i++;
           }
         🚨 PIÈGE ÉLIMINATOIRE : NE JAMAIS faire un 'break' sauvage au milieu 
            d'une boucle 'for' pour une recherche ! Les profs mettent 0 sur le critère.
 [ ] 4.2 Recherche d'extremum (Min / Max) :
         - Initialiser la valeur min/max avec le PREMIER élément du tableau :
           valeurMax = tab[0];
           indiceMax = 0;
         - Faire tourner la boucle de 1 à TAILLE - 1 (et pas depuis 0).
         🚨 PIÈGE : Ne JAMAIS initialiser le max à 0 ou le min à 9999 !
            Si le tableau contient des notes négatives, initialiser le max à 0 est faux !
 [ ] 4.3 Protection systématique des divisions par zéro :
         Avant de diviser par un compteur ou un effectif, TOUJOURS tester :
         if (nbElements > 0)
         {
             moyenne = somme / nbElements;
         }
         else
         {
             cout << "Impossible de calculer : aucune note valide." << endl;
         }

--------------------------------------------------------------------------------
 [PHASE 5] FORMATAGE, STYLE ALLMAN & INDENTATION (Coeff 2)
--------------------------------------------------------------------------------
 [ ] 5.1 Style Allman strict :
         TOUTES les accolades ouvrantes '{' et fermantes '}' sont SEULES sur 
         leur propre ligne et parfaitement alignées avec l'instruction parente.
         CORRECT (Allman) :
             if (condition)
             {
                 action();
             }
         INTERDIT (K&R) :
             if (condition) {
                 action();
             }
 [ ] 5.2 Indentation rigoureusement constante :
         4 espaces par niveau de bloc. Aucune ligne qui dépasse ou flotte.

--------------------------------------------------------------------------------
 [PHASE 6] COMPILATION & TESTS LOCAUX (Ne jamais soumettre sans tester !)
--------------------------------------------------------------------------------
 [ ] 6.1 Compiler dans VS Code avec 'Ctrl + Maj + B' ou en terminal :
         g++ -Wall -Wextra -Werror -pedantic main.cpp -o main.exe
         -> Le code DOIT compiler avec 0 erreur et 0 warning !
 [ ] 6.2 Tester le scénario nominal de l'énoncé :
         Vérifier que la sortie écran correspond au mot près à l'exemple.
 [ ] 6.3 Tester les cas limites :
         [ ] Saisie d'une valeur hors-bornes dès la première tentative.
         [ ] Saisie de la valeur d'arrêt dès le début (ex: 999).
         [ ] Élément recherché situé en toute première position (indice 0).
         [ ] Élément recherché situé en dernière position (indice TAILLE-1).
         [ ] Élément recherché TOTALEMENT ABSENT du tableau.
 [ ] 6.4 Vérifier que le programme ne plante pas (pas de boucle infinie, pas de
         dépassement d'indice de tableau, pas de division par zéro).

 4. SQUELETTE CANONIQUE DES 5 MODÈLES D'ALGORITHMES OFFICIELS
================================================================================

--------------------------------------------------------------------------------
 MODÈLE 1 : L'ÉCHANGE DE DEUX VALEURS
--------------------------------------------------------------------------------
// val1, val2 >> Échanger les deux valeurs >> val1, val2
copieVal1 = val1;
val1 = val2;
val2 = copieVal1;

--------------------------------------------------------------------------------
 MODÈLE 2 : LA SAISIE-VÉRIFICATION D'UNE VALEUR
--------------------------------------------------------------------------------
// (clavier) >> Saisir et vérifier la note dans [0..20] >> note
for ( ; ; )
{
    cout << "Entrez une note comprise entre " << NOTE_MIN << " et " << NOTE_MAX << " : ";
    cin >> note;

    if ((note >= NOTE_MIN) && (note <= NOTE_MAX))
    {
        break; // Valeur correcte : on sort de la boucle
    }

    cout << "Erreur : la note doit etre comprise entre " << NOTE_MIN << " et " << NOTE_MAX << " !" << endl;
}

--------------------------------------------------------------------------------
 MODÈLE 3 : PARCOURS COMPLET AVEC TRAITEMENT SYSTÉMATIQUE
--------------------------------------------------------------------------------
// notes, EFFECTIF >> Calculer la somme de toutes les notes >> somme
somme = 0;
for (i = 0; i < EFFECTIF; i++)
{
    somme += notes[i];
}

--------------------------------------------------------------------------------
 MODÈLE 4 : PARCOURS COMPLET AVEC TRAITEMENT CONDITIONNÉ
--------------------------------------------------------------------------------
// notes, EFFECTIF, SEUIL_ADMISSION >> Compter les notes >= seuil >> nbAdmis
nbAdmis = 0;
for (i = 0; i < EFFECTIF; i++)
{
    if (notes[i] >= SEUIL_ADMISSION)
    {
        nbAdmis++;
    }
}

--------------------------------------------------------------------------------
 MODÈLE 5 : RECHERCHE DE PREMIÈRE OCCURRENCE (PARCOURS PARTIEL AVEC ARRÊT)
--------------------------------------------------------------------------------
// etudiants, EFFECTIF, idRecherche >> Trouver l'étudiant recherché >> trouve, indiceEtudiant
trouve = false;
i = 0;
while (!trouve && (i < EFFECTIF))
{
    if (etudiants[i].id == idRecherche)
    {
        trouve = true;
    }
    else
    {
        i++;
    }
}

if (trouve)
{
    cout << "Etudiant trouve a l'indice : " << i << endl;
}
else
{
    cout << "Aucun etudiant ne porte cet identifiant." << endl;
}

--------------------------------------------------------------------------------
 MODÈLE 6 : RECHERCHE D'EXTREMUM (MINIMUM OU MAXIMUM)
--------------------------------------------------------------------------------
// notes, EFFECTIF >> Trouver la note maximale et sa position >> noteMax, indiceMax
noteMax = notes[0];
indiceMax = 0;

for (i = 1; i < EFFECTIF; i++)
{
    if (notes[i] > noteMax)
    {
        noteMax = notes[i];
        indiceMax = i;
    }
}


================================================================================
 5. LES 7 PIÈGES ÉLIMINATOIRES VUS PAR PATRICK ETCHEVERRY
================================================================================

1. OUBLI DU CARTOUCHE D'EN-TÊTE :
   -> Sanction immédiate : Note 0/20 attribuée sans regarder le code.
2. LE 'break' DANS UNE BOUCLE 'for' :
   -> Interdit absolu si vous cherchez un élément dans un tableau. 
   -> Une recherche se code avec 'while (!trouve && i < TAILLE)'.
3. LA VARIABLE 'int' PARTOUT :
   -> Si une note va de 0 à 20 ou qu'un indice ne peut pas être négatif, 
      utilisez 'unsigned short int' ou 'unsigned int'.
4. LES NOMBRES MAGIQUES EN DUR DANS LE CODE :
   -> Écrire 'for (i = 0; i < 15; i++)' ou 'if (note > 20)' en dur sans constante
      nommée 'EFFECTIF' ou 'NOTE_MAX' fait perdre 2 points sur les conventions.
5. INITIALISER LE MAX À 0 OU LE MIN À UNE VALEUR ARBITRAIRE :
   -> Toujours initialiser avec tab[0] et démarrer la boucle à 1.
6. LA DIVISION PAR ZÉRO :
   -> Calculer une moyenne sans tester 'if (nbElements > 0)' fait planter 
      le programme ou produit un 'nan'.
7. CONFONDRE TAILLE ET DERNIER INDICE :
   -> Un tableau de taille 10 va de l'indice 0 à 9. Accéder à 'tab[10]' est 
      un dépassement de mémoire (segfault / corruption).
