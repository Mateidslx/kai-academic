    Principe de la décomposition alternative

    Décomposition alternative - Définition

    Une décomposition alternative[1] exprime le fait que la résolution d'un problème P de nature complexe équivaut à résoudre selon les cas le sous-problème P1 ou bien le sous-problème P2 ou bien... le sous-problème Pn.

    Les décompositions alternatives permettent de décrire des solutions algorithmiques du type "faire ça si on est dans tel cas, faire ceci si on est dans tel autre cas ... faire cela dans tous les autres cas."

    [1] nommée aussi décomposition conditionnelle.

    Formalisme de la décomposition alternative

    Formalisme général (1/2)

    Signification : Le problème P se résout en solutionnant selon les cas :

    • le sous-problème P1 si la condition A est vraie ou bien,
    • le sous-problème P2 si la condition B est vraie ou bien,
    • ... puis
    • le sous-problème Pn si la condition N est vraie.

    Formalisme général (2/2)

    De ce fait, la résolution du problème P consistera à résoudre :

    • le sous-problème dont la condition de traitement est vérifiée ou bien,
    • aucun des sous-problèmes si aucune des conditions n'est vérifiée.

    On retiendra que les conditions doivent être exprimées de sorte à ce qu'elles soient exclusives les unes des autres (il ne peut y avoir deux conditions vraies en même temps) et ceci quelque soit l'ordre de lecture des conditions.

    Exemples généraux

    Décomposition Si

    Signification :

    • Le problème P se résout en solutionnant le sous-problème P1 si la condition A est vérifiée.
    • Si la condition A n'est pas vérifiée, il n'y a rien à faire, le problème P est considéré résolu.

    Décomposition Si - Sinon

    Signification : le problème P se résout en solutionnant le sous-problème P1 si la condition A est vérifiée ou bien le problème P2 dans tous les autres cas (condition A non vérifiée).

    Décomposition Si - Si

    Signification : Le problème P :

    • se résout en solutionnant le sous-problème P1 si la condition A est vérifiée ou bien,
    • se résout en solutionnant le sous-problème P2 si la condition B est vérifiée ou bien,
    • est considéré résolu dans tous les autres cas (condition A et condition B non vérifiées).

    Décomposition Si - Si - Sinon

    Signification : Le problème P se résout en solutionnant :

    • le sous-problème P1 si la condition A est vérifiée ou bien,
    • le sous-problème P2 si la condition B est vérifiée ou bien,
    • le sous-problème P3 dans tous les autres cas (condition A et condition B non vérifiées).

    Exclusion mutuelle des conditions

    Le fait de rendre les conditions exclusives les unes des autres permet d'éviter des cas d'erreur, de renforcer la robustesse de l'algorithme mais aussi sa flexibilité : les conditions peuvent être évaluées dans n'importe quel ordre, ce qui permet de réaménager la structure de l'algorithme sans conséquences néfastes :

    Structure plus simple... mais moins flexible

    L'exclusion mutuelle des conditions n'est pas respectée, le bon fonctionnement de l'algorithme est dépendant de l'ordre d'évaluation des conditions...

    Des conditions non exclusives rendent le code sensible à l’ordre d’évaluation. Toute modification de cet ordre peut alors changer le comportement du programme, ce qui le rend plus fragile et moins flexible.

    Cas du switch

    Contexte d'usage

    De nombreux problèmes ont des solutions dont la mise en œuvre dépend de la valeur d'une information.

    Exemple : Proposer un algorithme qui affiche en toutes lettres un chiffre dont la valeur est saisie au clavier. Comportement attendu

    Solution possible : Étudier la valeur du chiffre saisi et agir en conséquence :

    • Si la valeur égale 0, afficher "zéro" ;
    • Si la valeur égale 1, afficher "un" ;
    • ...
    • Si la valeur égale 9, afficher "neuf" ;
    • Dans tous les autres cas afficher "erreur".

    Prise en compte de ces cas de figure en programmation

    Les situations qui nécessitent d'étudier la valeur d'une information sont tellement fréquentes que la plupart des langages de programmation proposent une structure conditionnelle spécialisée pour gérer ce type de situation.

    Selon les langages de programmation, elle se nommera switch (C++, Java ou Php par exemple) ou encore case (Ada).

    Représentation algorithmique du switch

    Signification : La résolution du problème P consiste à solutionner, selon la valeur d'expression :

    • Le problème P1 si la valeur d'expression égale valeur1 ;
    • Le problème P2 si la valeur d'expression égale valeur2 ;
    • ...
    • Le problème Pn si la valeur d'expression égale valeurN ;

    Exemple de décomposition avec un switch

    Rappel sur la notion d'expression

    Une expression peut être :

    • une simple variable ;
    • un appel de fonction ;
    • un calcul combinant des valeurs, des variables et/ou des appels de fonctions.

    Switch avec une variable

    Signification : La résolution du problème Traiter la valeur du dé consiste à solutionner, selon la valeur stockée dans valeurDe :

    • le sous-problème Relancer le dé si valeurDe égale 1 ;
    • le sous-problème Passer son tour si valeurDe égale 2 ;
    • le sous-problème Changer de sens si valeurDe égale 3 ;
    • le sous-problème Diviser le score par 2 si valeurDe égale 4 ;
    • le sous-problème Donner un gage si valeurDe égale 5 ;
    • le sous-problème Faire appel si valeurDe égale 6.

    Switch avec un calcul

    Signification : La résolution du problème Traiter la valeur du dé avec bonus consiste à solutionner, selon la valeur résultant du calcul de valeurDe + bonus :

    • le sous-problème Donner un gage si valeurDe + bonus égale 5 ;
    • le sous-problème Faire appel si valeurDe + bonus égale 6 ;
    • le sous-problème Donner joker si valeurDe + bonus égale 7 ;
    • le sous-problème Doubler le score si valeurDe + bonus égale 8 ;
    • le sous-problème Relancer 2 fois le dé si valeurDe + bonus égale 9 ;
    • le sous-problème Déclarer la victoire si valeurDe + bonus égale 10.

    Du bon usage du switch

    La décomposition alternative de type switch est à utiliser lorsque :

    • la résolution d'un problème consiste à déterminer si la valeur d'une expression est égale à des valeurs particulières en nombre fini ;
    • le nombre de cas à étudier est supérieur à 2 (sinon un Si-Sinon suffit).

    Codage de la décomposition alternative

    Syntaxe

    En C++, le codage de la décomposition alternative est réalisé au moyen des instructions if, else et switch. Leur syntaxe est la suivante : 

    
 if (condition)
 {
     Liste des instructions à déclencher 
     si la condition est vérifiée
 }
                         

    
 if (condition)
 {
    Liste des instructions à déclencher 
    si la condition est vérifiée
 }
 else
 {
     Liste des instructions à déclencher 
     si la condition n'est pas vérifiée
 }
                     
    
 switch (expression)
 {
   case valeur1 :
   Liste des instructions à déclencher 
   si expression = valeur1
   break;

   case valeur2 :
   Liste des instructions à déclencher 
   si expression = valeur2
   break;

   ...

    case valeurN :
    Liste des instructions à déclencher 
    si expression = valeurN
    break;

    default :
    Liste des instructions à déclencher
    dans tous les autres cas
    break;
 }

    Accolades dans les structures if-else (2/2)

    Le fait de placer des accolades sur les blocs d'instructions à déclencher permet :

    • d'améliorer la lisibilité du code en mettant en évidence l'ensemble des instructions exécutées selon que la condition est vérifiée ou pas ;
    • de faciliter la maintenance du code : que l'on doive ajouter ou supprimer des instructions, peu importe, la structure complète du if-else est déjà en place ;

    Paroles d'experts...

    Bonne pratique

    Quel que soit le nombre d'instructions placées dans une structure de contrôle, ces instructions doivent toujours être délimitées par des accolades, même lorsqu'il n'y a qu'une seule instruction.

    "Dans les structures de contrôle, employez des accolades pour créer des blocs, que le bloc contienne 20 lignes ou 1 seule."

    Steve Mc Connell Tout sur le code - Pour concevoir du logiciel de qualité, dans tous les langages, 2005, page 471.

    "All flow control primitives (if, else, while, for, do, switch and case) should be followed by a block, even if it is empty."

    Erik Nyquist, Industrial Strength C++, Pentice Hall, 1997

    Clauses break et default dans le switch

    Pour l'instruction switch, la clause default peut être supprimée si on est certain que expression aura une des valeurs listées dans les clauses case. 

    
 switch (expression)
 {
   case valeur1 :
   Liste des instructions à déclencher 
   si expression = valeur1
   break;
    
   case valeur2 :
   Liste des instructions à déclencher 
   si expression = valeur2
   break;
    
   ...
    
   case valeurN :
   Liste des instructions à déclencher 
   si expression = valeurN
   break;
     
   default :
   Liste des instructions à déclencher
   dans tous les autres cas
   break;
 }

    Attention : il est important de ne pas oublier l'instruction break qui permet de sortir de la structure conditionnelle dès lors que la valeur associée à expression a été traitée.

    Condition Si déclenchant une instruction

    
 // nbre >> Indiquer si le nombre est positif >> (écran)
 if (nbre > 0)
 {
   cout << "Afficher le nombre est positif";
 }

    Condition Si déclenchant plusieurs instructions

    
 // score >> Diminuer le score >> (écran)
 if (score > 0)
 {
   score = score - 1;
   cout << score;
 }

    Condition Si-Sinon

    
 // note >> Indiquer si l'étudiant a la moyenne >> (écran)
 if (note >= 10)
 {
   cout << "Vous avez la moyenne";
 }
 else
 {
   cout << "Vous n'avez pas la moyenne";                
 }

    Variante :

    
 // note >> Indiquer si l'étudiant a la moyenne >> (écran)
 cout << (note >= 10 ? "Vous avez la moyenne" : "Vous n'avez pas la moyenne");

    Condition Si-Si

    
 // note >> Indiquer si l'étudiant a la moyenne >> (écran)
 if (note >= 10)
 {
   cout << "Vous avez la moyenne";
 }
 else
 {
   if (note < 10)
   {
     cout << "Vous n'avez pas la moyenne";
   }
 }

    Condition Si-Si : Attention

    Le codage ci-dessous est incorrect : Si la 1ère condition est vérifiée, la machine évaluera quand même la seconde condition... 

    
 // note >> Indiquer si l'étudiant a la moyenne >> (écran)
 if (note >= 10)
 {
   cout << "Vous avez la moyenne";
 }

 if (note < 10)
 {
   cout << "Vous n'avez pas la moyenne";
 }

    Condition Si-Si-Sinon

    
 // note >> Indiquer si l'étudiant a la moyenne >> (écran)
 if (note < 10)
 {
   cout << "Vous n'avez pas la moyenne";
 }
 else if (note == 10)
 {
   cout << "Vous avez juste la moyenne";
 }
 else
 {
   cout << "Vous avez au dessus de la moyenne";
 }

    Conditions multiples

   cout << "Vous n'avez pas la moyenne";

   cout << "Vous avez juste la moyenne";

    Codage du switch : Exemple (1/2)

    Codage de l'algorithme qui affiche en toutes lettres un chiffre à partir de sa valeur numérique :

    Codage du switch : Exemple (2/2)

    
 // Afficher chiffre sous forme alphabétique >> (écran)

 // (clavier) >> Saisir un chiffre >> chiffre
 cout << "Entrez un chiffre :";
 cin >> chiffre;

 // chiffre >> Afficher le chiffre en toutes lettres
 switch (chiffre)
 {
   case 0  : cout << "zéro";   break;
   case 1  : cout << "un";     break;
   case 2  : cout << "deux";   break;
   case 3  : cout << "trois";  break;
   case 4  : cout << "quatre"; break;
   case 5  : cout << "cinq";   break;
   case 6  : cout << "six";    break;
   case 7  : cout << "sept";   break;
   case 8  : cout << "huit";   break;
   case 9  : cout << "neuf";   break;
   default : cout << "erreur"; break;
 }

    Du bon usage du switch : Rappel

    S'il n'y a qu'un ou deux cas à étudier et que le nombre de cas n'est pas censé évoluer, on utilisera de préférence une structure de type if-else : 

    
 /* trouve >> Analyser le résultat de la 
    recherche >> (écran) */
 switch (trouve)
 {
   case true :
   cout << "recherche fructueuse"; 
   break;
    
   case false :
   cout << "recherche infructueuse"; 
   break;
 }
                         
    
 /* trouve >> Analyser le résultat de la 
    recherche >> (écran) */
 if (trouve == true)
 {
   cout << "recherche fructueuse";
 }
 else
 {
   cout << "recherche fructueuse";
 }
