1. La Pyramide des Mémoires & les Deux Principes de Localité

En physique des semi-conducteurs, il est impossible de concevoir une mémoire qui soit simultanément infiniment rapide, immense en capacité et économiquement bon marché. Pour contourner cette limite physique, les architectes d'ordinateurs organisent la mémoire sous forme d'une pyramide hiérarchique :

Niveau Hiérarchique Technologie Physique Temps d'Accès Typique Capacité Ordre de Grandeur Géré Par
1. Registres CPU Bistables SRAM internes < 0.5 ns (1 cycle) Quelques centaines d'octets Compilateur / Assembleur
2. Cache L1 (Instruction / Data) SRAM ultra-rapide sur le silicium 1 à 2 ns (3 à 4 cycles) 32 Ko à 64 Ko par cœur Matériel (Contrôleur Cache)
3. Cache L2 SRAM sur puce 3 à 7 ns (10 à 14 cycles) 256 Ko à 1 Mo par cœur Matériel
4. Cache L3 (Partagé) SRAM haute densité partagée 10 à 25 ns (30 à 60 cycles) 8 Mo à 64 Mo Matériel
5. RAM Principale DRAM (condensateurs rafraîchis) 50 à 100 ns (150 à 250 cycles) 8 Go à 64 Go Système d'Exploitation (OS)
6. Stockage de Masse (SSD/NVMe) Mémoire Flash NAND / NVMe 10 à 50 µs (10 000 fois plus lent que la RAM) 512 Go à 4 To OS (Système de Fichiers)

LES DEUX PRINCIPES CARDINAUX DE LOCALITÉ

Pourquoi le cache fonctionne-t-il avec un taux de réussite (Hit Rate) de plus de 95% dans la vraie vie ? Grâce à deux propriétés empiriques des programmes informatiques :

1. Localité Temporelle

Si un emplacement mémoire est référencé à un instant donné, il a une probabilité extrêmement forte d'être réaccédé très prochainement (ex: la variable compteur d'une boucle for(int i=0;...) ou le corps d'une fonction récursive).

2. Localité Spatiale

Si un emplacement mémoire est référencé, les données situées à des adresses contiguës ou très proches ont une probabilité maximale d'être lues prochainement (ex: parcours séquentiel des cases d'un tableau ou exécution séquentielle des instructions du code).

2. Micro-Architecture du Cache, Adressage & Formule AMAT

Dans un cache, l'information ne voyage jamais octet par octet mais par paquets entiers appelés lignes de cache (ou blocs), typiquement de 64 octets. Toute adresse mémoire émise par le processeur est découpée en 3 champs binaires indépendants :

TAG (Étiquette) Identifiant d'unicité en RAM
INDEX Numéro de l'ensemble (Set)
OFFSET Position dans la ligne
1. L'Offset (Déplacement)

Si un bloc contient $B$ octets, le champ Offset possède $k$ bits tels que $2^k = B$.
Exemple : Bloc de 64 octets $\implies 2^6 = 64 \implies$ Offset = 6 bits.

2. L'Index

Si le cache comporte $S$ ensembles, le champ Index compte $m$ bits tels que $2^m = S$.
Exemple : 512 ensembles $\implies 2^9 = 512 \implies$ Index = 9 bits.

3. Le Tag (Étiquette)

Porte tous les bits restants de l'adresse :
$ ext{Tag} = ext{Largeur\_Adresse} - ( ext{Index} + ext{Offset})$.
Comparé au tag stocké dans la ligne pour vérifier si c'est un HIT.

Les 3 Modes de Correspondance (Mapping)

  • • Correspondance Directe (Direct Mapped) : Chaque adresse de RAM ne peut aller que dans une et une seule ligne du cache ($ ext{Ligne} = ext{Bloc} \pmod{ ext{Nb\_Lignes}}$). Matériel simple mais conflits fréquents si deux adresses rivalisent pour la même ligne.
  • • Entièrement Associatif (Fully Associative) : Un bloc de RAM peut être placé dans n'importe quelle ligne libre. Zéro conflit, mais nécessite de comparer tous les tags en parallèle (très coûteux en surface et énergie).
  • • Associatif par Ensembles de N Voies (N-Way Set Associative) — STANDARD : Le cache est divisé en ensembles comportant chacun $N$ lignes (typiquement 2, 4, 8 ou 16 voies). Un bloc va dans un ensemble fixe donné par l'Index, mais peut occuper n'importe laquelle des $N$ voies de cet ensemble.

Temps d'Accès Moyen à la Mémoire (AMAT — Average Memory Access Time)

Dans tout examen de M. Moulin, le calcul de performance mémoire passe par l'équation AMAT :

AMAT = Temps_Hit + Taux_de_Miss × Pénalité_de_Miss

Attention : Le Temps_Hit est TOUJOURS payé, même en cas de défaut, car le contrôleur doit d'abord interroger le cache pour constater l'échec avant de basculer sur la RAM principale.

3. Théorie de Richard Hamming : Distance & Code Correcteur (7, 4)

Dans les années 1940 aux Laboratoires Bell, les cartes perforées provoquaient des erreurs de lecture aléatoires qui arrêtaient les calculs des ordinateurs la nuit. Excédé de devoir recommencer ses programmes le matin, Richard Hamming conçut une théorie mathématique permettant non seulement de détecter une erreur binaire, mais de localiser sa position exacte et de la corriger automatiquement sans réémission !

DISTANCE DE HAMMING & CAPACITÉ DE CORRECTION

La Distance de Hamming $d(u, v)$ entre deux mots binaires de même longueur est le nombre exact de bits où ils diffèrent. Pour un code de détection/correction de distance minimale $d_{\min}$ :

  • • Pour détecter $e$ erreurs simples : il faut $d_{\min} \ge e + 1$.
  • • Pour corriger $c$ erreurs simples : il faut $d_{\min} \ge 2c + 1$.
• Bit de parité simple : $d_{\min} = 2 \implies$ Détecte 1 erreur, en corrige 0.
• Code de Hamming (7, 4) : $d_{\min} = 3 \implies$ Détecte jusqu'à 2 erreurs, et corrige 1 erreur certaine (SEC — Single Error Correction) !

L'Algorithme du Code de Hamming (7, 4) Pas-à-Pas

On transmet 4 bits de données utiles ($d_1, d_2, d_3, d_4$) protégés par 3 bits de parité de contrôle ($p_1, p_2, p_4$). Total = 7 bits transmis.

Position dans le mot 1 (2⁰) 2 (2¹) 3 4 (2²) 5 6 7
Nature du Bit p₁ (Parité) p₂ (Parité) d₁ (Donnée) p₄ (Parité) d₂ (Donnée) d₃ (Donnée) d₄ (Donnée)
Index Binaire 001 010 011 100 101 110 111
1. Équations d'Émission (Calcul des Parités Paires) :

• p₁ couvre toutes les positions ayant le bit 0 à '1' (pos 1, 3, 5, 7) : $p_1 = d_1 \oplus d_2 \oplus d_4$
• p₂ couvre toutes les positions ayant le bit 1 à '1' (pos 2, 3, 6, 7) : $p_2 = d_1 \oplus d_3 \oplus d_4$
• p₄ couvre toutes les positions ayant le bit 2 à '1' (pos 4, 5, 6, 7) : $p_4 = d_2 \oplus d_3 \oplus d_4$

2. Équations de Réception & Calcul du Syndrome $S = (s_4, s_2, s_1)$ :

• $s_1 = b_1 \oplus b_3 \oplus b_5 \oplus b_7$
• $s_2 = b_2 \oplus b_3 \oplus b_6 \oplus b_7$
• $s_4 = b_4 \oplus b_5 \oplus b_6 \oplus b_7$

Magie mathématique de Hamming : Si le syndrome $S = 000_2 = 0 \implies$ Zéro erreur détectée !
Si $S e 0 \implies$ La valeur décimale du mot binaire $(s_4 s_2 s_1)_2$ donne DIRECTEMENT le numéro de position exact (de 1 à 7) du bit inversé ! Il suffit d'inverser ce bit pour réparer le mot instantanément.

4. Atelier Pièges d'Examen de M. Moulin

1 Calcul des bits d'Index dans un cache Associatif par Ensembles

Erreur classique : Calculer l'Index en fonction du nombre total de lignes de cache.
Règle absolue : L'Index désigne le numéro de l'ensemble (Set) ! Si un cache compte 1024 lignes au total et qu'il est 4-way set associative (4 voies par ensemble) : il y a $ ext{Nb\_Ensembles} = 1024 / 4 = 256$ ensembles. Le champ Index compte donc $\log_2(256) = \mathbf{8 ext{ bits}}$, et non 10 bits !

2 Positionnement des bits de parité dans le mot de Hamming

Les bits de parité se placent exclusivement aux positions puissances de 2 (pos 1, 2, 4, 8...), JAMAIS au début ou à la fin du mot. Si vous les placez aux positions 1, 2, 3, le calcul du syndrome ne donnera plus la position du bit erroné.

3 Write-Through vs Write-Back

En Write-Through, chaque écriture CPU met à jour le cache ET la RAM en même temps (simple mais sature le bus). En Write-Back, on n'écrit que dans le cache et on marque la ligne avec un bit Dirty (sale). La RAM n'est mise à jour QUE lorsque la ligne sale est évincée par l'algorithme LRU !

5. Exercices Résolus Pas-à-Pas (TD Type M. Moulin)

Exercice : Détection & Correction Hamming (7, 4) du mot `1 1 0 1 1 1 0` Partiel R1.03

Étape 1 : Indexation des bits reçus b₁ à b₇ :

b₁=1, b₂=1, b₃=0, b₄=1, b₅=1, b₆=1, b₇=0

Étape 2 : Calcul des bits du Syndrome S = (s₄, s₂, s₁) :

• s₁ = b₁ ⊕ b₃ ⊕ b₅ ⊕ b₇ = 1 ⊕ 0 ⊕ 1 ⊕ 0 = 0
• s₂ = b₂ ⊕ b₃ ⊕ b₆ ⊕ b₇ = 1 ⊕ 0 ⊕ 1 ⊕ 0 = 0
• s₄ = b₄ ⊕ b₅ ⊕ b₆ ⊕ b₇ = 1 ⊕ 1 ⊕ 1 ⊕ 0 = 1

Étape 3 : Interprétation du Syndrome :

Le mot binaire du syndrome est S = (s₄ s₂ s₁)₂ = 100₂ = 4 décimal.
Puisque S ≠ 0, il y a une erreur : c'est exactement le bit n°4 (b₄) qui est corrompu !

Étape 4 : Correction et Extraction des données utiles :

Inversion de b₄ : b₄ passe de 1 à 0.
Mot corrigé : 1 1 0 0 1 1 0.
Données utiles (positions 3, 5, 6, 7) : d₁=0, d₂=1, d₃=1, d₄=0 $\implies$ Mot d'origine = 0110₂.

4 Questions
QUESTION 1 / 4 Caches Découpage

Un système 32 bits utilise un cache associatif par ensembles de 4 voies (4-way). La capacité du cache est de 32 Ko et chaque ligne contient 32 octets. Combien de bits sont alloués au champ Tag ?

Explication détaillée :
1. Taille de ligne = 32 octets $= 2^5 \implies \mathbf{ ext{Offset} = 5 ext{ bits}}$.
2. Nombre total de lignes = $32 ext{ Ko} / 32 ext{ octets} = 1024$ lignes.
3. Avec 4 voies par ensemble, Nombre d'ensembles = $1024 / 4 = 256 = 2^8 \implies \mathbf{ ext{Index} = 8 ext{ bits}}$.
4. Sur une adresse 32 bits, $\mathbf{ ext{Tag} = 32 - (8 + 5) = 19 ext{ bits}}$.
QUESTION 2 / 4 Calcul AMAT

Un processeur possède un cache avec un temps d'accès de 2 ns (Hit Time), un taux de défaut (Miss Rate) de 5%, et une pénalité de défaut (accès RAM) de 60 ns. Quel est l'AMAT ?

Explication : $ ext{AMAT} = T_{ ext{hit}} + ( ext{Miss\_Rate} imes ext{Miss\_Penalty}) = 2 ext{ ns} + (0.05 imes 60 ext{ ns}) = 2 + 3 = \mathbf{5.0 ext{ ns}}$.
QUESTION 3 / 4 Hamming Distance

Pour être capable de corriger automatiquement 2 erreurs binaires simultanées dans un mot, quelle doit être la distance de Hamming minimale ($d_{\min}$) du code ?

Explication : Théorème de Hamming : pour corriger $c$ erreurs, les sphères de Hamming de rayon $c$ centrées sur les mots de code valides ne doivent pas se chevaucher, ce qui impose $d_{\min} \ge 2c + 1$. Pour $c=2$, $2(2) + 1 = 5$.
QUESTION 4 / 4 Politiques d'Écriture

Quelle est la principale caractéristique de la politique d'écriture en cache dite « Write-Back » ?

Explication : Le Write-Back évite d'engorger le bus mémoire externe : l'écriture se fait à la vitesse fulgurante de la SRAM du cache et la ligne est étiquetée "Dirty" (modifiée). La recopie en DRAM n'a lieu qu'au dernier moment, lors de l'éviction de la ligne.
