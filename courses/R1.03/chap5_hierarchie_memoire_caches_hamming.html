1. La Pyramide de la Hiérarchie Mémoire

Les technologies de mémoire sont soumises à un compromis physique incontournable : plus une mémoire est rapide, plus elle est chère et plus sa capacité est réduite.

Niveau Type de Mémoire Temps d'Accès Typique Capacité Typique Localisation
0 Registres internes CPU $< 0.5$ ns (1 cycle) Quelques centaines d'octets Sur le cœur silicium
1 Cache L1 (Instructions + Données) $1 - 2$ ns (~4 cycles) 32 à 64 Ko par cœur Sur le cœur silicium
2 Cache L2 $3 - 7$ ns (~14 cycles) 512 Ko à 1 Mo par cœur Sur le die du CPU
3 Cache L3 (Partagé) $10 - 20$ ns (~50 cycles) 16 à 96 Mo partagés Sur le die du CPU
4 Mémoire Centrale RAM (DDR4/DDR5) $50 - 80$ ns (~200 cycles) 8 à 64 Go Barrettes DIMM externes
5 Stockage Secondaire (SSD NVMe) $10 - 50$ $\mu$s 512 Go à 4 To Lignes PCIe

2. Les Deux Principes Fondamentaux de Localité

Le fonctionnement miraculeux des mémoires caches (qui permettent un taux de succès cache hit supérieur à 95%) repose sur deux propriétés universelles des programmes :

  • Localité Temporelle : Si un emplacement mémoire a été accédé à l'instant $t$, il a une très forte probabilité d'être accédé à nouveau dans un avenir proche (ex: variables dans une boucle for ou while).
  • Localité Spatiale : Si un emplacement mémoire à l'adresse $A$ a été accédé, les emplacements contigus $A+1, A+2$ ont une très forte probabilité d'être accédés prochainement (ex: parcours séquentiel d'un tableau d'éléments en C).

3. Détection et Correction d'Erreurs : Le Code de Hamming

Les mémoires modernes (en particulier la mémoire ECC des serveurs) intègrent le code de Hamming pour détecter et corriger automatiquement les inversions de bits provoquées par les rayons cosmiques ou le bruit thermique.

  • Distance de Hamming : Nombre de positions binaires où deux mots de même longueur diffèrent.
  • Critères de Correction :
    • Pour détecter $d$ erreurs simples : la distance minimale du code doit être $d_{min} \ge d + 1$.
    • Pour corriger $t$ erreurs : la distance minimale du code doit être $d_{min} \ge 2t + 1$.
  • Code de Hamming (7, 4) : Code 4 bits de données avec 3 bits de parité intercalés aux puissances de 2 (positions 1, 2, 4). Il permet de corriger automatiquement 1 bit erroné (SEC) et de détecter 2 bits erronés (DED).

QUESTION 1 / 4 R1.03 • Ch.5

Quels sont les deux grands principes de localité justifiant l'efficacité des mémoires caches ?

Explication Pédagogique : La localité temporelle (boucles de code, variables récurrentes) et la localité spatiale (tableaux parcourus en mémoire, instructions consécutives) permettent aux caches de deviner avec plus de 95% de réussite les données nécessaires.
QUESTION 2 / 4 R1.03 • Ch.5

Quelle est la hiérarchie correcte des mémoires, de la plus rapide (mais plus petite) à la plus lente (mais plus grande) ?

Explication Pédagogique : La pyramide de mémoire classe par vitesse décroissante : Registres (1 cycle) -> Cache L1 (quelques cycles) -> Cache L2 -> Cache L3 -> Mémoire vive RAM (dizaines de ns) -> Stockage secondaire SSD/HDD (ms).
QUESTION 3 / 4 R1.03 • Ch.5

En quoi l'architecture matérielle d'un GPU (processeur graphique) diffère-t-elle radicalement de celle d'un CPU (processeur central) ?

Explication Pédagogique : Le CPU consacre l'essentiel de sa surface de silicium au contrôle (prédiction de branchement, exécution hors ordre) et à de gigantesques mémoires caches. Le GPU consacre sa surface presque exclusivement aux unités de calcul (ALU) pour traiter en parallèle des millions de pixels ou tenseurs.
QUESTION 4 / 4 R1.03 • Ch.5

En quoi consiste le goulot d'étranglement de Von Neumann (Von Neumann Bottleneck) ?

Explication Pédagogique : Comme les instructions et les données doivent transiter par le même bus externe pour aller de la RAM au CPU, le processeur passe une part considérable de son temps à attendre l'arrivée des données. C'est ce goulot qui a motivé l'introduction des mémoires caches hiérarchiques.
