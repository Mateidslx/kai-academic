R1.12 • CHAPITRE 2

Outils de Candidature : CV Technique, GitHub & e-Portfolio

Enseignant Référent : Équipe Pédagogique PPP — IUT de Bayonne et du Pays Basque (Campus d'Anglet)

Structure d'un CV de développeur moderne, mise en valeur des hard skills et soft skills, conception de l'e-portfolio professionnel, vitrine GitHub et préparation aux entretiens de stage.

1. Les Règles d'Or du CV Technique d'un Étudiant en BUT Informatique

Les recruteurs techniques (Lead Developers, CTOs) passent moins de 30 secondes sur un CV. Pour maximiser l'impact :

  1. Le Titre Cible Précis :
    Bannir les titres flous comme « Étudiant en informatique ».
    Privilégier un titre orienté vers le besoin de l'entreprise : « Étudiant en BUT Informatique (IUT d'Anglet) — Recherche de Stage Développement C / Linux / Web (10 semaines dès Avril) ».
  2. Le Bloc « Hard Skills » Structuré par Domaines :
    • Langages : C ANSI (C99/C11), C++ moderne, Bash/Shell, JavaScript ES6+, SQL, HTML5/CSS3.
    • Bases de Données & Modélisation : Merise (MCD/MLD), PostgreSQL, Oracle, SQLite.
    • Systèmes & Outils : Linux (Ubuntu, Debian), Git / GitHub, Valgrind, Make / CMake, VS Code.
    • Méthodologies : Agile Scrum, tests unitaires, accessibilité W3C WCAG, éco-conception RGESN.
  3. La Section « Projets Réalisés » (Projets Académiques & Personnels) :
    Plutôt qu'une simple liste de cours, décrire concrètement les SAÉs et projets sous forme de fiches d'impact :

    Plateforme KAI Study (Plateforme Académique Universitaire)

    • Conception et déploiement d'un portail web autonome de révision pour 20 modules de BUT 1 Informatique.

    • Intégration de 195 supports Moodle officiels, serveur HTTP local 0 ms latence et déploiement cloud VPS Oracle.

    • Respect strict des normes d'accessibilité W3C WCAG AAA pour la dyslexie (police Lexend, contrastes feutrés).

    • Stack : Python, HTML5/CSS3, JavaScript, systemd, Nginx, Cloudflare Tunnel.

  4. Les Liens Professionnels Cliquables : Profil GitHub soigné, profil LinkedIn à jour et URL de l'e-portfolio interactif.

2. Faire de son GitHub une Véritable Vitrine Professionnelle

  • Soigner le README.md de chaque dépôt public (description du projet, capture d'écran, instructions d'installation et de compilation avec gcc ou make).
  • Écrire des messages de commits propres et normalisés en anglais ou français structuré (ex: feat: implement Dijkstra pathfinding, fix: prevent memory leak in buffer allocator).
  • Vérifier qu'aucun jeton d'API, mot de passe ou clé privée SSH n'est accidentellement poussé sur les dépôts publics.

Atelier Pièges d'Examen & Erreurs Éliminatoires

Analyse comparative des erreurs les plus fréquemment commises en devoir sur table à l'IUT d'Anglet et des méthodes rigoureuses pour garantir le maximum de points :

1 Piège d'Examen n°1 : Confusion conceptuelle ou application mécanique sur « CV » sans vérifier les préconditions
❌ Erreur Classique en Partiel :

Appliquer directement une formule, une commande ou un patron lié à CV sur les données brutes de l'énoncé sans contrôler le domaine de validité, le typage ou les hypothèses initiales du chapitre Outils de Candidature : CV Technique, GitHub & e-Portfolio.

🔍 Pourquoi c'est sanctionné :

En partiel de R1.12, Équipe Pédagogique PPP insère systématiquement des données comportant un cas particulier (valeur nulle, ensemble vide, borne incluse/exclue, droit manquant ou contrainte implicite). Une application aveugle produit un résultat faux ou incomplet qui fait perdre 50% à 100% des points de la question.

✅ Réflexe Attendu à l'IUT :

Toujours commencer sa copie ou son script par expliciter les conditions d'application de CV : énoncer la règle officielle du cours, vérifier que les entrées respectent le contrat, puis dérouler la résolution pas à pas.

2 Piège d'Examen n°2 : Oubli des cas limites et erreurs d'inattention sur « Portfolio »
❌ Erreur Classique en Partiel :

Tester ou rédiger sa solution uniquement sur le cas nominal général en ignorant les frontières de Portfolio (premier/dernier élément, cardinalité minimale/maximale, erreur de signe ou d'options).

🔍 Pourquoi c'est sanctionné :

Dans le barème officiel de l'IUT d'Anglet (Projet Personnel et Professionnel (PPP)), une part majeure des points est dédiée à la robustesse : Le Titre Cible Précis : Bannir les titres flous comme « Étudiant en informatique » . Privilégier un titre orienté vers le besoin de l'entreprise : « Étudiant en BUT Informatique (I Ignorer ce point conduit à une solution partielle immédiatement détectée par le correcteur.

✅ Réflexe Attendu à l'IUT :

Après avoir écrit la solution générale pour Portfolio, effectuer un test à la main (trace d'exécution sur table) avec la valeur minimale, la valeur maximale et un cas dégénéré pour valider la solidité de la démarche.

3 Piège d'Examen n°3 : Absence de justification et résultat brut parachuté sur « GitHub »
❌ Erreur Classique en Partiel :

Écrire uniquement le résultat final, la commande finale ou le schéma final concernant GitHub sans détailler les étapes intermédiaires ni citer la propriété du cours mobilisée.

🔍 Pourquoi c'est sanctionné :

Équipe Pédagogique PPP rappelle qu'une réponse exacte mais non justifiée en contrôle continu ou en partiel de R1.12 ne permet pas d'évaluer le raisonnement de l'étudiant : en cas de moindre erreur de calcul à la dernière ligne, la note tombe à zéro.

✅ Réflexe Attendu à l'IUT :

Structurer chaque réponse en 3 temps : 1) Rappel du principe ou théorème (GitHub), 2) Détail explicite des étapes de transformation avec les valeurs de l'énoncé, 3) Conclusion encadrée et interprétation concrète.
