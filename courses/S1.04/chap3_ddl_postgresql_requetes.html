Chapitre 3 : Script DDL PostgreSQL, Données Réalistes & Requêtes Décisionnelles

Écriture du script SQL complet avec CREATE TABLE, contraintes CHECK, insertions massives cohérentes et requêtes de reporting avec agrégats.

1. Création Physique de la Base PostgreSQL : Script DDL

Le Data Definition Language (DDL) permet de matérialiser le MLD validé au sein du SGBD relationnel PostgreSQL avec toutes ses contraintes d'intégrité : 

-- Suppression préventive des tables si existantes
DROP TABLE IF EXISTS reservation CASCADE;
DROP TABLE IF EXISTS activite CASCADE;
DROP TABLE IF EXISTS prestataire CASCADE;
DROP TABLE IF EXISTS client CASCADE;

-- 1. Table Prestataire
CREATE TABLE prestataire (
    id_prestataire SERIAL PRIMARY KEY,
    raison_sociale VARCHAR(100) NOT NULL,
    siret CHAR(14) NOT NULL UNIQUE,
    commune VARCHAR(50) NOT NULL,
    telephone VARCHAR(15) NOT NULL
);

-- 2. Table Activité
CREATE TABLE activite (
    id_activite SERIAL PRIMARY KEY,
    nom_activite VARCHAR(100) NOT NULL,
    description TEXT,
    tarif_ht NUMERIC(8, 2) NOT NULL CHECK (tarif_ht >= 0.00),
    id_prestataire INT NOT NULL,
    CONSTRAINT fk_activite_prestataire
        FOREIGN KEY (id_prestataire)
        REFERENCES prestataire(id_prestataire)
        ON DELETE CASCADE
);

-- 3. Table Client
CREATE TABLE client (
    id_client SERIAL PRIMARY KEY,
    nom VARCHAR(50) NOT NULL,
    prenom VARCHAR(50) NOT NULL,
    email VARCHAR(120) NOT NULL UNIQUE,
    date_inscription DATE NOT NULL DEFAULT CURRENT_DATE
);

-- 4. Table Réservation
CREATE TABLE reservation (
    id_reservation SERIAL PRIMARY KEY,
    id_client INT NOT NULL,
    id_activite INT NOT NULL,
    date_session TIMESTAMP NOT NULL,
    nb_participants INT NOT NULL CHECK (nb_participants BETWEEN 1 AND 50),
    statut_paiement VARCHAR(20) DEFAULT 'EN_ATTENTE' CHECK (statut_paiement IN ('EN_ATTENTE', 'PAYE', 'ANNULE')),
    CONSTRAINT fk_res_client FOREIGN KEY (id_client) REFERENCES client(id_client),
    CONSTRAINT fk_res_activite FOREIGN KEY (id_activite) REFERENCES activite(id_activite)
);

2. Requêtes d'Analyse Métier Avancées (Jointures & Agrégations)

Une fois les données insérées, les gestionnaires de la plateforme Ongi Etorri interrogent la base pour extraire des indicateurs de gestion : 

-- Requête : Chiffre d'affaires total et nombre de participants par prestataire
SELECT 
    p.raison_sociale,
    p.commune,
    COUNT(r.id_reservation) AS nb_reservations_total,
    SUM(r.nb_participants) AS total_participants,
    SUM(r.nb_participants * a.tarif_ht * 1.20) AS chiffre_affaires_ttc
FROM prestataire p
INNER JOIN activite a ON p.id_prestataire = a.id_prestataire
INNER JOIN reservation r ON a.id_activite = r.id_activite
WHERE r.statut_paiement = 'PAYE'
GROUP BY p.id_prestataire, p.raison_sociale, p.commune
HAVING SUM(r.nb_participants) >= 5
ORDER BY chiffre_affaires_ttc DESC;
