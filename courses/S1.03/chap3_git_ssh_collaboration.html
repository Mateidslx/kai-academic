1. Le Modèle Conceptuel Interne de Git

Contrairement aux anciens systèmes centralisés (SVN, CVS) qui stockaient des différences entre versions (diffs), Git est un système distribué de gestion de versions reposant sur un graphe acyclique dirigé (DAG) d'instantanés (snapshots) immuables.

  • Blob : Stocke le contenu binaire pur d'un fichier, identifié par le hash SHA-1 de son contenu.
  • Tree : Représente un répertoire, associant des noms de fichiers à des hashes de blobs ou de sous-arbres.
  • Commit : Instantané complet du projet pointant vers un arbre racine, des métadonnées (auteur, date, message) et le ou les commits parents.

2. Les 3 Zones de Travail de Git

  1. 1. Working Directory (Répertoire de Travail) :
    Les fichiers physiques réels présents sur le disque dur avec lesquels le développeur interagit dans son éditeur de code.
  2. 2. Staging Area / Index (Zone de Préparation) :
    Zone tampon où sont sélectionnés les fichiers et morceaux de code (hunks) qui feront partie du prochain commit (via git add).
  3. 3. Git Directory / Repository (Dépôt Git .git/) :
    La base de données orientée objets contenant l'historique complet et permanent de tous les commits validés.

3. Commandes Stratégiques de Collaboration d'Équipe

# Créer et basculer sur une nouvelle branche fonctionnelle :
git checkout -b feature/module-tri

# Examiner l'état de l'index et des fichiers modifiés :
git status

# Ajouter des modifications de manière chirurgicale (par blocs) :
git add -p src/tri.cpp

# Valider le commit avec un message normé (Conventional Commits) :
git commit -m "feat(tri): implementation de l'algorithme de tri fusion en O(n log n)"

# Récupérer et fusionner les modifications distantes proprement :
git fetch origin
git rebase origin/main

# Pousser la branche de travail vers la forge :
git push -u origin feature/module-tri

4. Authentification Sécurisée par Clé SSH Ed25519

L'authentification par mot de passe sur GitHub/GitLab est obsolète pour des raisons de sécurité. L'authentification par paire de clés cryptographiques à courbe elliptique Ed25519 est la norme obligatoire : 

# Génération de la paire de clés Ed25519 sans mot de passe vide :
ssh-keygen -t ed25519 -C "matei.but1@univ-pau.fr" -f ~/.ssh/id_ed25519_uppa

# Ajout de la clé publique (~/.ssh/id_ed25519_uppa.pub) sur le compte GitLab/GitHub
# Configuration du fichier ~/.ssh/config pour automatiser la connexion :
# Host gitlab.univ-pau.fr
#     IdentityFile ~/.ssh/id_ed25519_uppa
#     User git
