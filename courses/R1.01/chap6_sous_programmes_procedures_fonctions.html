1. La Modularité : Diviser pour Régner

Un programme monolithique de 1000 lignes dans une seule fonction main() est illisible, impossible à débugger et non réutilisable. La modularité consiste à décomposer une application complexe en unités fonctionnelles autonomes appelées sous-programmes (fonctions et procédures).

LES 4 AVANTAGES DE LA MODULARITÉ :

1. Lisibilité : Le main() devient un chef d'orchestre épuré de 20 lignes qui exprime la logique métier de haut niveau.

2. Réutilisabilité : Un sous-programme écrit une fois (ex: saisirNoteControlee) peut être appelé 50 fois depuis divers endroits du logiciel.

3. Testabilité unitaire : On peut tester et valider mathématiquement chaque fonction isolément avant de l'intégrer au système complet.

4. Encapsulation : Les variables internes du sous-programme sont privées et protégées contre les interférences accidentelles du reste du programme.

2. Procédure ou Fonction : La Distinction Formelle

En C++, les deux concepts sont syntaxiquement déclarés sous le mot générique de « fonction », mais leur rôle sémantique en algorithmique est radicalement différent :

Critère Procédure (void) Fonction Pure (TypeDeRetour)
Définition Action qui réalise un traitement, modifie son environnement (affichage, fichier) ou mute des variables passées par référence. Mécanisme de calcul qui évalue et renvoie un unique résultat par son nom via l'instruction return.
Type de Retour void (mot-clé indiquant le vide, aucun retour). Un type valide : int, double, bool, string...
Mode d'Appel Instruction autonome suivie d'un point-virgule :
afficherMenu();
echanger(x, y);		 Utilisée au sein d'une expression (affectation, condition) :
double moy = calculerMoyenne(tab, n);
if (estPremier(n)) ...
Règle d'Or IUT À choisir si le traitement produit 0 résultat ou plus de 1 résultat (via paramètres modifiables). À choisir dès que le traitement produit exactement un résultat sans effet de bord.

3. Modèle Mémoire : La Pile d'Exécution (Call Stack) & Portée des Variables

Comprendre les sous-programmes exige de visualiser ce qui se passe physiquement dans la mémoire RAM lors d'un appel :

LE MÉCANISME DU CADRE DE PILE (STACK FRAME) :

1. Empilement à l'appel : Lors de l'appel d'un sous-programme, le système suspend la fonction appelante et alloue un nouveau cadre de pile au sommet de la mémoire. Ce cadre contient l'adresse de retour (où reprendre l'exécution) et alloue l'espace pour tous les paramètres formels et les variables locales.

2. Cloisonnement strict (Portée / Scope) : Une variable locale déclarée dans un sous-programme n'existe que dans ce cadre. Deux fonctions différentes peuvent avoir une variable nommée compteur sans jamais interférer : ce sont deux cases RAM physiques totalement distinctes !

3. Dépilement au return : Dès que le sous-programme se termine (accolade fermante ou return), son cadre de pile est instantanément détruit. Toutes ses variables locales s'évaporent de la mémoire.

RÈGLE SPÉCIALE D'AMPHI : LA TRANSMISSION DES TABLEAUX EN C/C++ :

En C et C++, un tableau est automatiquement transmis par adresse (dégradation en pointeur). Par convention dans le cours de M. Etcheverry, on n'ajoute pas de & :
• Tableau modifiable : void remplir(int tableau[], unsigned int taille);
• Tableau non modifiable : void afficher(const int tableau[], unsigned int taille);
Obligation absolue : Toujours transmettre la taille du tableau immédiatement après le tableau !

5. La Règle d'Or d'Ordonnancement des Paramètres

Lors des examens sur table, M. Etcheverry sanctionne le désordre dans la signature des sous-programmes. L'ordre des paramètres dans la parenthèse doit refléter rigoureusement les natures formelles du dictionnaire :

L'ORDRE CANONIQUE STRICT DANS LA SIGNATURE :

void sousProgramme ( /* 1. DONNÉES */ const Type& d1, Type d2,

/* 2. DONNÉES/RÉSULTATS */ Type& dr1,

/* 3. RÉSULTATS */ Type& r1 );

6. Atelier Pièges d'Examen : Les Fautes Courantes en Sous-Programmes

PIÈGE CARDINAL Oubli du Symbole & lors d'une Modification (Passage par valeur involontaire) -4 points

❌ Code Inefficace

void saisir(int val)
{
cin >> val;
}

⚠️ Mécanisme du Bug

val est transmise par valeur : le système en crée une copie locale. cin remplit cette copie. Dès l'accolade fermante, la copie est détruite. Dans le main, la variable d'origine n'a pas bougé d'un bit !

✅ Solution 20/20

void saisir(int& val)
{
cin >> val;
}

Le & crée un alias direct sur la case mémoire d'origine.

CRASH MÉMOIRE Retourner une Référence vers une Variable Locale Détruite Interdit Absolu

Ne jamais écrire int& fonction() { int temp = 5; return temp; } : la case temp est détruite dès le return. Le programme appelant reçoit une référence vers une zone mémoire fantôme, provoquant un comportement indéfini (Undefined Behavior) ou un crash immédiat.

7. Exercice Guidé Intégral : Procédures, Fonctions & Tableaux

Voici une architecture modulaire complète respectant l'intégralité des standards de l'IUT d'Anglet : 

/*
 * Programme : GestionNotesModulaire
 * But : Démonstration complète des sous-programmes avec conformité Allman et Core Guidelines.
 * Auteur : Matéi de Saint Leger
 */

#include <iostream>
#include <iomanip>
using namespace std;

// =============================================================================
// PROTOTYPES DES SOUS-PROGRAMMES (CONTRATS D'INTERFACE)
// =============================================================================

void echanger (int& a, int& b);
// Rôle : Échange le contenu de deux entiers en mémoire.
// Données/Résultats : a (int&), b (int&)

void saisirNote (float& note, float borneMin, float borneMax);
// Rôle : Saisie contrôlée d'une note dans l'intervalle [borneMin ; borneMax].
// Données : borneMin (float), borneMax (float)
// Résultats : note (float&)

float calculerMoyenne (const float tableauNotes[], unsigned int nbNotes);
// Rôle : Calcule la moyenne arithmétique d'un tableau de notes sans le modifier.
// Données : tableauNotes (const float[]), nbNotes (unsigned int)
// Précondition : nbNotes > 0

// =============================================================================
// FONCTION PRINCIPALE MAIN
// =============================================================================

int main (void)
{
    const unsigned int NB_MAX = 5;
    float notesPromo[NB_MAX];

    // Remplissage via la procédure modulaire
    for (unsigned int i = 0; i < NB_MAX; ++i)
    {
        cout << "Étudiant " << (i + 1) << " : ";
        saisirNote(notesPromo[i], 0.0, 20.0);
    }

    // Calcul via la fonction pure
    float moyenne = calculerMoyenne(notesPromo, NB_MAX);

    cout << fixed << setprecision(2);
    cout << "
Moyenne de la promotion : " << moyenne << " / 20" << endl;

    return 0;
}

// =============================================================================
// CORPS DES SOUS-PROGRAMMES
// =============================================================================

void echanger (int& a, int& b)
{
    int temp = a;
    a = b;
    b = temp;
}

void saisirNote (float& note, float borneMin, float borneMax)
{
    do
    {
        cin >> note;
        if (note < borneMin || note > borneMax)
        {
            cout << "Note invalide. Veuillez entrer une valeur entre " 
                 << borneMin << " et " << borneMax << " : ";
        }
    }
    while (note < borneMin || note > borneMax);
}

float calculerMoyenne (const float tableauNotes[], unsigned int nbNotes)
{
    float somme = 0.0;
    for (unsigned int i = 0; i < nbNotes; ++i)
    {
        somme = somme + tableauNotes[i];
    }
    return somme / static_cast<float>(nbNotes);
}
