1. Genèse Historique & Définition Formelle d'un Algorithme

Le mot algorithme tire son étymologie de la latinisation du nom du savant et mathématicien persan Muhammad ibn Mūsā al-Khwārizmī (vers 820 ap. J.-C., Maison de la Sagesse de Bagdad). Dans son traité pionnier Kitāb al-mukhtaṣar fī ḥisāb al-jabr wal-muqābala (qui donna également naissance au mot « algèbre »), al-Khwārizmī formalisa des méthodes systématiques, rigoureuses et reproductibles pour résoudre des équations linéaires et quadratiques sans dépendre de l'intuition d'un individu.

DÉFINITION ACADÉMIQUE FORMELLE (M. ETCHEVERRY — IUT D'ANGLET)

Un algorithme est une suite finie, ordonnée et univoque d'instructions élémentaires exécutables sans ambiguïté par un opérateur (humain ou machine), opérant sur un ensemble déterminé de données d'entrée pour produire, en un temps fini, un ensemble de résultats de sortie conformes aux spécifications.

Pour qu'une suite d'instructions soit qualifiée d'algorithme valide au sens académique et industriel, elle doit impérativement respecter quatre propriétés cardinales :

1 Finitude (Arrêt garanti)

L'exécution doit obligatoirement s'achever après un nombre fini d'opérations élémentaires, quelle que soit la combinaison d'entrées choisie. Un programme qui boucle indéfiniment est défaillant : il ne constitue pas un algorithme.

2 Univocité (Déterminisme strict)

À chaque étape de l'algorithme, l'action suivante est déterminée de manière unique, mathématique et sans la moindre ambiguïté. Deux exécutions avec des données d'entrée identiques produiront rigoureusement la même trajectoire et le même résultat.

3 Calculabilité / Efficacité

Toute opération élémentaire spécifiée doit pouvoir être exécutée concrètement par l'agent d'exécution (la machine ou le processeur) avec des ressources matérielles réelles et dans un intervalle de temps physiquement délimité.

4 Contrat d'Interface (Entrées / Sorties)

Un algorithme possède un domaine de définition formel : il consomme zéro ou plusieurs valeurs d'entrée bien typées ($\{E\}$) et génère une ou plusieurs valeurs de sortie ($\{S\}$) répondant à un but mesurable.

Distinguer Algorithme, Programme et Heuristique

• Algorithme : Concept abstrait universel, indépendant de tout langage de programmation et de tout système d'exploitation (ex: algorithme du tri par sélection).

• Programme : Traduction concrète d'un algorithme dans un langage informatique particulier (ex: C++, C, Python) compilé ou interprété sur une machine matérielle.

• Heuristique : Méthode de calcul rapide fournissant une solution approchée ou probable sans garantie mathématique d'optimalité ni certitude d'arrêt dans tous les cas de figure.

2. L'Architecture de von Neumann : Modèle Matériel de la Machine

Tout algorithme implémenté sur un ordinateur moderne repose sur le modèle unifié proposé par le mathématicien et physicien John von Neumann en 1945. Contrairement aux calculateurs électromécaniques primitifs dont le câblage physique devait être reconfiguré pour chaque calcul, l'ordinateur von Neumann repose sur le principe fondamental du programme enregistré : les instructions de code et les données manipulées partagent la même mémoire centrale.

Le Cycle Universel d'Exécution du Processeur (Fetch-Decode-Execute)

À chaque impulsion de l'horloge système (rythmée à plusieurs milliards de cycles par seconde, soit en GHz), le processeur répète inlassablement ce cycle en 4 phases :

Phase 1

Fetch (Recherche)

Le processeur charge l'instruction pointée par le registre IP (Instruction Pointer) depuis la mémoire RAM vers le registre IR.

Phase 2

Decode (Décodage)

L'Unité de Contrôle analyse l'opcode binaire pour identifier l'opération à effectuer (ex: additionner, sauter à une adresse) et ses opérandes.

Phase 3

Execute (Exécution)

L'Unité Arithmétique et Logique réalise le calcul physique ou le test booléen sur les transistors des registres internes.

Phase 4

Store / Increment

Le résultat est écrit dans un registre ou renvoyé en RAM, et le pointeur d'instruction IP avance vers l'instruction suivante.

3. De la Source au Binaire : Le Cycle de Compilation C++

Le processeur est totalement incapable de lire du code C++ directement. Il ne comprend qu'une suite de 0 et de 1 (le langage machine). Le passage du fichier texte source main.cpp jusqu'au fichier binaire exécutable main.exe (Windows) ou main (Linux) mobilise une chaîne d'outils (toolchain) rigoureusement séquencée en 4 étapes majeures :

Étape Outil GCC / Clang Fichier d'Entrée Fichier Produit Rôle Exact & Opérations Effectuées
1. Préprocesseur cpp main.cpp main.i (temporaire) Traite toutes les directives commençant par #. Il copie-colle textuellement le contenu des bibliothèques en-tête (ex: #include <iostream>), remplace les macros (#define) et supprime l'intégralité des commentaires.
2. Compilation g++ -S main.i main.s (texte assembleur) Analyse lexicale, syntaxique et sémantique. Traduit le code C++ validé en instructions assembleur spécifiques à l'architecture du processeur (x86_64 ou ARM64). C'est ici que sont détectées les fautes de syntaxe (point-virgule manquant, types incompatibles).
3. Assemblage as main.s main.o ou main.obj Convertit le texte assembleur en code objet binaire relogeable. Le code machine est généré, mais les adresses des fonctions externes (comme cout ou les sous-programmes situés dans d'autres fichiers) restent encore non résolues.
4. Édition de Liens ld / collect2 main.o + libstdc++.a main.exe (Exécutable) Lie le fichier objet avec les bibliothèques standard du système d'exploitation. Résout toutes les adresses mémoire des symboles externes et produit le binaire autonome exécutable directement par le système d'exploitation.

COMMANDE DE COMPILATION OFFICIELLE ENSEIGNÉE À L'IUT D'ANGLET : 

g++ -Wall -Wextra -Werror -pedantic -std=c++17 main.cpp -o main.exe

• -Wall : Active l'ensemble des avertissements essentiels du compilateur (Warnings: All).

• -Wextra : Active les vérifications supplémentaires approfondies (variables inutilisées, comparaisons signées/non-signées).

• -Werror : Règle d'or d'amphi : convertit chaque avertissement en erreur bloquante. La compilation échoue tant que le code n'est pas irréprochable.

• -std=c++17 : Impose la conformité stricte au standard C++ moderne ISO 2017.

4. Anatomie Complète d'un Programme C++ (Ligne par Ligne)

À l'IUT d'Anglet, chaque programme rendu en travaux pratiques ou en partiel machine doit respecter la tripartition stricte et l'indentation Allman (accolades ouvrantes et fermantes seules sur leur propre ligne, alignées verticalement). 

/*
 * Programme : ConversionMonetaire
 * But : Calculer et afficher la contre-valeur en Dollars US d'une somme saisie en Euros.
 * Date de modification : 19/10/2026
 * Auteur : Matéi de Saint Leger (Groupe TD2 / TP4)
 * Remarques : Taux fixe conventionnel 1 EUR = 1.0850 USD
 */

#include <iostream>  // Bibliothèque officielle des flux d'entrée/sortie (cin / cout)
#include <iomanip>   // Manipulateurs de flux pour formater l'affichage monétaire

using namespace std; // Évite d'écrire systématiquement std:: devant chaque mot-clé

int main (void)
{
    // =========================================================================
    // 1. DÉCLARATION DES CONSTANTES & TYPES
    // =========================================================================
    const double TAUX_CONVERSION = 1.0850; // Constante symbolique en majuscules

    // =========================================================================
    // 2. DÉCLARATION DU DICTIONNAIRE DES VARIABLES LOCALES
    // =========================================================================
    double montantEuros;   // Montant saisi par l'utilisateur en Euros (Nature : D)
    double montantDollars; // Montant calculé en Dollars US (Nature : R)

    // =========================================================================
    // 3. SÉQUENCE DES TRAITEMENTS EXÉCUTABLES
    // =========================================================================
    // Inviter l'utilisateur et récupérer la donnée d'entrée
    cout << "Veuillez saisir un montant en Euros : ";
    cin >> montantEuros;

    // Calcul de transformation arithmétique
    montantDollars = montantEuros * TAUX_CONVERSION;

    // Restitution formatée du résultat à l'écran
    cout << fixed << setprecision(2);
    cout << montantEuros << " EUR équivaut exactement à " 
         << montantDollars << " USD." << endl;

    // Code de retour système (0 = fin d'exécution normale sans anomalie)
    return 0;
}

Décryptage Minutieux des Éléments Clés :

1. #include <iostream>

Demande au préprocesseur d'importer le fichier d'en-tête déclarant les objets globaux de flux cin (character input) et cout (character output). Sans cette ligne, le compilateur rejette toute tentative de lecture clavier ou d'affichage console.

2. using namespace std;

Définit l'espace de nommage par défaut. Tous les identificateurs de la bibliothèque standard C++ sont encapsulés dans le namespace std. Cette directive évite de devoir préfixer chaque appel : std::cout devient simplement cout.

3. int main (void)

Point d'entrée universel et unique du programme exécuté par le chargeur du système d'exploitation. Le mot-clé int spécifie que la fonction renvoie un code d'état entier au système. Le mot-clé void indique que la fonction ne prend aucun argument depuis la ligne de commande.

4. Les flux cin >> et cout <<

L'opérateur << (« chevron vers la gauche ») insère des données dans le tube de sortie écran. L'opérateur >> (« chevron vers la droite ») extrait les octets tapés au clavier depuis le tampon système pour les ranger dans la case mémoire de la variable cible.

5. return 0;

Indique au système d'exploitation hôte que le programme s'est achevé avec plein succès (valeur conventionnelle POSIX EXIT_SUCCESS = 0). Une valeur non nulle (1, -1) indique un code d'erreur.

5. Représentation Mémoire & Système de Types Primitifs

Le C++ est un langage compilé, statiquement et fortement typé. Chaque variable déclarée réserve un bloc d'octets contigus en mémoire RAM dont la taille physique et l'interprétation binaire sont figées définitivement dès la phase de compilation.

bool 1 octet 8 bits true (1) ou false (0) Indicateurs logiques, drapeaux, résultats de comparaisons booléennes.
char 1 octet 8 bits -128 à +127 (ou 0 à 255 si unsigned) Caractère unique représenté selon la table ASCII standard (ex: 'A' = 65, '0' = 48).
short 2 octets 16 bits -32 768 à +32 767 Petits entiers signés, économie d'espace en mémoire.

L'OPÉRATEUR sizeof(type) :

L'opérateur C++ sizeof(...) est évalué à la compilation. Il renvoie la taille exacte en octets occupée par un type ou une variable sur la machine hôte. Exemple : sizeof(int) retourne 4 sur architecture standard x86_64.

6. Le Dogme Fondateur d'Etcheverry : « Concevoir avant de Coder »

L'erreur la plus dévastatrice chez l'étudiant débutant consiste à ouvrir son éditeur de code et à taper des lignes au hasard dès la lecture du sujet. Cette attitude mène directement à des programmes bogués, incohérents et impossibles à débugger. À l'IUT d'Anglet, une démarche formelle rigoureuse en trois phases disjointes est exigée :

1 Phase 1 : Analyse

« Quoi faire ? » (Boîte Noire)

Comprendre le problème sans penser au code. Définir le But formel à l'infinitif, identifier l'ensemble des données d'entrée $\{E\}$, l'ensemble des résultats $\{S\}$, les contraintes mathématiques $\{P\}$, et dresser un jeu de test exhaustif à 3 scénarios.

2 Phase 2 : Conception

« Comment faire ? » (Arbre d'Actions)

Décomposer le problème général de manière descendante en sous-problèmes élémentaires grâce aux 3 structures de base : séquence ($||$), alternative (losange/hexagone) et itération (boucle). Rédiger le Dictionnaire des Données ($D, R, D/R, INT$).

3 Phase 3 : Traduction

« Traduction mécanique C++ »

Le codage n'est que la transcription directe de l'arbre d'actions validé. On applique le style Allman strict, on compile avec -Werror, on vérifie l'absence de fuite mémoire avec Valgrind et on valide le comportement avec le jeu de tests.

7. Atelier Pièges d'Examen : Les Fautes Éliminatoires aux Partiels

Voici les erreurs récurrentes sanctionnées par les enseignants lors des partiels écrits et machines de R1.01 :

PIÈGE 1 La Division Entière Silencieuse (70% d'échecs au premier contrôle) Grave

❌ Code Erroné de l'Étudiant

double moyenne = 15 / 2;

L'étudiant s'attend à ce que moyenne vaille 7.5 car elle est déclarée en double.

⚠️ Mécanisme du Bug

Les deux constantes 15 et 2 sont des entiers stricts (int). En C++, la division de deux entiers produit un entier tronqué : 15 / 2 vaut 7. Ce résultat 7 est ensuite converti en 7.0.

✅ Solution 20/20 Conforme

double moyenne = 15.0 / 2; // ou static_cast<double>(a) / b

Forcer au moins un des deux opérandes en virgule flottante pour que le compilateur effectue une division réelle.

PIÈGE 2 Variable Non Initialisée (Valeurs « Poubelles » en RAM) Critique

❌ Code Erroné de l'Étudiant

int compteur;
compteur = compteur + 1;

L'étudiant suppose que la mémoire allouée à compteur est automatiquement à zéro.

⚠️ Mécanisme du Bug

En C++, la déclaration d'une variable locale ne nettoie pas la mémoire. La variable hérite des bits résiduels qui traînaient dans la case RAM (ex: -858993460). Votre calcul part d'une valeur absurde.

✅ Solution 20/20 Conforme

int compteur = 0;
// Toujours initialiser toute variable dès sa création !

Initialiser explicitement toute variable dès sa déclaration.

PIÈGE 3 Le Point-Virgule Traître après une Condition if Vicelard

❌ Code Erroné de l'Étudiant

if (note >= 10);
{
cout << "Admis";
}

Un point-virgule machinal a été ajouté après la parenthèse du if.

⚠️ Mécanisme du Bug

Le point-virgule termine immédiatement l'instruction conditionnelle comme une instruction vide. Le bloc { cout << "Admis"; } devient un bloc isolé indépendant qui sera toujours exécuté, même si note vaut 2 !

✅ Solution 20/20 Conforme

if (note >= 10)
{
cout << "Admis";
}

Zéro point-virgule après la parenthèse de test.

8. Exercice Guidé Intégral : Conversion Monétaire & Trace Mémoire

ÉNONCÉ :

9. Auto-Évaluation Interactive : Validez Vos Connaissances (5 Questions)

Sélectionnez la réponse exacte pour chaque question de partiel ci-dessous :

Question 1 : Que vaut l'expression double x = 7 / 2; en C++ ?

Explication : En C++, le type de l'opération arithmétique dépend exclusivement des opérandes. Les constantes 7 et 2 sont des int, donc la division entière produit 3. Ce n'est qu'après que ce 3 entier est affecté au double x, devenant 3.0.

Question 2 : Dans la machine de von Neumann, quel composant assure le séquençage et le décodage des instructions ?

Explication : L'Unité de Contrôle (UC) est le chef d'orchestre du CPU : elle gère le pointeur d'instruction, lit l'instruction en RAM, la décode et ordonne à l'ALU de réaliser les calculs.

Question 3 : Quelle étape de la chaîne de compilation remplace les directives #include par le texte réel des en-têtes ?

Explication : Le préprocesseur est un outil de traitement purement textuel qui s'exécute en toute première étape avant la moindre vérification grammaticale C++.
