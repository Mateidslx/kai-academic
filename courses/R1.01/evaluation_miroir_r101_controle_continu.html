Exercice 1 (5 points) — Spécifications & Trace d'Algorithme

Voir explication ➔

On considère le sous-programme C++ suivant conçu selon les normes de l'IUT d'Anglet :

void mystere(int a, int& b)
{
    int c;
    c = a * 2;
    b = b + c;
    a = b - 4;
}

Dans la fonction principale main(), on exécute la séquence suivante :

int x = 3;
int y = 5;
mystere(x, y);
cout << "x = " << x << ", y = " << y << endl;

Exercice 1 — Spécifications & Table de Trace Pas-à-Pas

1. Modes de passage des paramètres formels

  • Paramètre a (par valeur) : Une COPIE indépendante de la variable passée en argument est créée dans la pile d'exécution du sous-programme. Toute modification de a à l'intérieur de mystere n'affectera jamais la variable d'origine x du main.
  • Paramètre b (par référence &) : b est un ALIAS direct (référence mémoire) de la variable y. Toute modification apportée à b modifie instantanément y en mémoire centrale !

2. Table de trace pas-à-pas

Étape d'exécution x (main) y / b a (copie) c (locale)
Avant l'appel (dans main) 3 5 - -
Entrée dans mystere(x, y) 3 5 (alias y) 3 indéterminé
c = a * 2; (3 * 2) 3 5 3 6
b = b + c; (5 + 6) 3 11 3 6
a = b - 4; (11 - 4) 3 11 7 6
Retour dans main (après destruction pile) 3 11 détruit détruit

3. Sortie affichée à l'écran

x = 3, y = 11
Vérification : x est resté intact à 3 car passé par valeur. y a été écrasé à 11 car lié par référence &.

Exercice 2 — Permutation Mémoire & Procédures

Le piège de la copie locale : Dans le code initial, val1 et val2 sont passés par valeur. La permutation s'exécute parfaitement sur les deux copies temporaires, mais dès que l'accolade fermante } est atteinte, la pile est libérée et les variables du main n'ont absolument pas bougé !

Code corrigé aux normes IUT d'Anglet

#include <iostream>
using namespace std;

// Prototype avec références obligatoires
void echanger(int& val1, int& val2);

int main(void)
{
    // VARIABLES
    int nombreA = 10;
    int nombreB = 20;

    // TRAITEMENTS
    cout << "Avant echange : A = " << nombreA << ", B = " << nombreB << endl;
    echanger(nombreA, nombreB);
    cout << "Apres echange : A = " << nombreA << ", B = " << nombreB << endl;

    return 0;
}

void echanger(int& val1, int& val2)
{
    // VARIABLES
    int temp;

    // TRAITEMENTS
    temp = val1;
    val1 = val2;
    val2 = temp;
}

Exercice 3 — Calcul de Remise & Division Flottante

Attention absolue au piège C++ : taux = remise / 100; avec deux entiers effectue une division entière : 20 / 100 = 0 ! Il faut impérativement diviser par 100.0f flottant. 
float calculerPrixReduit(float prixInitial, unsigned short int remise)
{
    // VARIABLES
    float tauxDecimal;
    float prixFinal;

    // TRAITEMENTS
    tauxDecimal = static_cast<float>(remise) / 100.0f;
    prixFinal = prixInitial * (1.0f - tauxDecimal);

    if (remise > 50)
    {
        cout << "Remise exceptionnelle appliquee !" << endl;
    }

    return prixFinal;
}

Exercice 4 — Algorithme du Minimum dans un Tableau

Sous-programme C++ avec passage sécurisé

void trouverMinimum(const int tab[], unsigned int taille, int& minVal, unsigned int& minPos)
{
    // PRECONDITION : taille > 0
    minVal = tab[0];
    minPos = 0;

    for (unsigned int i = 1; i < taille; ++i)
    {
        if (tab[i] < minVal)
        {
            minVal = tab[i];
            minPos = i;
        }
    }
}

Complexité temporelle : L'algorithme effectue exactement $(N - 1)$ comparaisons pour un tableau de taille $N$. Sa complexité est donc en $\mathcal{O}(N)$ (linéaire), ce qui est optimal car chaque élément doit être examiné au moins une fois.
