1. Fondements du C & Cartographie Mémoire d'un Processus

Créé en 1972 par Dennis Ritchie aux laboratoires Bell pour développer le système d'exploitation UNIX, le langage C est souvent qualifié d'« assembleur portable ». Contrairement aux langages modernes dotés d'un ramasse-miettes automatique (Java, Python, C#), le C n'offre aucun filet de sécurité : le programmeur contrôle directement les octets et les adresses physiques de la machine.

2. Les Pointeurs : Adressage Direct & Déréférencement

Un pointeur est une variable dont la valeur n'est pas un nombre métier (comme un prix ou un âge), mais l'adresse mémoire où est stockée une autre variable.

LES DEUX OPÉRATEURS FONDAMENTAUX DU C (M. DALMAU) :

1. L'opérateur d'adresse & : Placée devant une variable existante, l'expression &x renvoie l'adresse hexadécimale de la première case octet occupée par x en RAM.

2. L'opérateur de déréférencement * : Placée devant un pointeur, l'expression *ptr permet d'accéder (en lecture ou en écriture) au contenu réel situé à l'adresse pointée.

Code C Illustratif : 
int age = 19;
int* ptrAge = &age; // ptrAge stocke l'adresse de age

*ptrAge = 20; // Modifie directement age !
printf("Age = %d\n", age); // Affiche 20 !
Schéma Mémoire en RAM :

• Case age (Adresse 0x1000) : contient 20 (4 octets).

• Case ptrAge (Adresse 0x2000) : contient l'adresse 0x1000 (8 octets sur 64 bits).

Écrire *ptrAge = 20 va suivre la flèche vers 0x1000 et y écrire 20.

LE POINTEUR NUL (NULL / nullptr) :

Un pointeur qui ne pointe encore vers aucune case valide doit impérativement être initialisé à NULL : int* p = NULL;. Tenter de lire ou d'écrire dans *p lorsque p == NULL provoque immédiatement un arrêt d'urgence du système d'exploitation : Segmentation fault (core dumped).

3. Arithmétique des Pointeurs & Équivalence Tableau-Pointeur

L'arithmétique des pointeurs ne fonctionne pas en octets unitaires, mais en unités d'éléments typés :

FORMULE D'INCRÉMENTATION D'UN POINTEUR :

Si ptr est un pointeur de type T* situé à l'adresse mémoire $A$, l'expression ptr + k pointe vers l'adresse mémoire :
AdresseCalculée = A + (k × sizeof(T))
Si ptr est un int* à l'adresse 0x1000, alors ptr + 1 vaut 0x1004 (car un int occupe 4 octets) !

LE THÉORÈME FONDAMENTAL DU LANGAGE C :

En C, l'écriture indicée tableau[i] est une abréviation syntaxique strictement équivalente à l'écriture pointeur :

tableau[i] <===> *(tableau + i)

4. Allocation Dynamique sur le Tas : malloc, calloc, realloc & free

Les tableaux statiques (ex: int tab[100];) ont une taille figée à la compilation. Si l'utilisateur a 101 éléments, le programme plante ; s'il en a 3, 97 cases sont gaspillées. L'allocation dynamique permet de réserver sur le Tas la taille exacte demandée au moment de l'exécution via la bibliothèque standard <stdlib.h>.

Fonction Signature C Rôle Exact & Particularité Mémoire
malloc void* malloc(size_t tailleOctets); Alloue un bloc contigu de $N$ octets. La mémoire n'est pas initialisée (elle contient des octets aléatoires poubelles). Renvoie NULL si la RAM est saturée.
calloc void* calloc(size_t nb, size_t tailleUnitaire); Alloue l'espace pour $N$ éléments et initialise tous les octets à zéro. Plus lent que malloc mais sécurisé.
realloc void* realloc(void* ptr, size_t nouvelleTaille); Agrandit ou rétrécit un bloc mémoire déjà alloué en préservant son contenu existant.
free void free(void* ptr); Obligatoire : Libère le bloc mémoire et le restitue au système d'exploitation.

LA RÈGLE D'OR DE M. SÉBASTIEN DALMAU :

1 malloc = 1 free. Toute zone réservée avec malloc doit obligatoirement être libérée avec free avant la fin de vie du programme. Immédiatement après avoir libéré un pointeur, remettez-le à NULL pour éviter tout accès illégal ultérieur :
free(monPointeur); monPointeur = NULL;

5. Détection des Fuites Mémoire (Memory Leaks) & Audit avec Valgrind

Une fuite mémoire survient lorsqu'un programme alloue un bloc sur le tas avec malloc, puis perd l'adresse de ce bloc (ex: en écrasant le pointeur ou en quittant la fonction) sans avoir appelé free. La case mémoire reste monopolisée pour rien jusqu'à saturer la RAM du serveur.

COMMANDE OFFICIELLE D'ÉVALUATION TP SOUS LINUX :

valgrind --leak-check=full --show-leak-kinds=all --track-origins=yes ./mon_programme

LE RAPPORT VALGRIND PARFAIT ATTENDU À L'EXAMEN (20/20) :

6. Atelier Pièges d'Examen : Les 4 Erreurs Mortelles avec les Pointeurs

FAUTE N°1 Oubli de sizeof() dans malloc (Corruption Mémoire Silencieuse) Destructeur

❌ Code Erroné

int* tab = malloc(10);

L'étudiant pense avoir alloué un tableau de 10 entiers.

⚠️ Mécanisme du Bug

malloc prend un nombre d'OCTETS. Le système alloue 10 octets, soit à peine 2 entiers et demi (4+4+2). Dès l'indice 3, vous écrivez en dehors de la zone autorisée : corruption de heap !

✅ Solution 20/20

int* tab = malloc(10 * sizeof(int));

Alloue exactement $10 imes 4 = 40$ octets.

FAUTE N°2 Le « Double Free » (Libérer Deux Fois le Même Pointeur) Crash SIGABRT

Appeler free(ptr); deux fois sur le même bloc mémoire détruit la table interne d'allocation de la glibc. Le système déclenche instantanément un signal d'abandon brutal free(): double free detected in tcache 2. Pour vous prémunir, écrivez toujours free(ptr); ptr = NULL; : en effet, free(NULL); est garanti sans danger par la norme C.

7. Exercice Guidé Intégral : Tableau Dynamique Sécurisé en C ANSI

Voici le programme type exigé au partiel machine par M. Sébastien Dalmau, compilé avec les drapeaux stricts -Wall -Wextra -Werror : 

/*
 * Programme : GestionTableauDynamique
 * But : Allocation dynamique d'un tableau d'entiers avec test d'échec et libération.
 * Enseignant : M. Sébastien Dalmau
 * Auteur : Matéi de Saint Leger
 */

#include <stdio.h>
#include <stdlib.h>

int main (void)
{
    // =========================================================================
    // VARIABLES
    // =========================================================================
    int taille = 0;
    int* tableau = NULL; // Toujours initialiser un pointeur à NULL !
    int somme = 0;

    // =========================================================================
    // 1. SAISIE DE LA TAILLE DU TABLEAU
    // =========================================================================
    printf("Combien d'entiers souhaitez-vous stocker ? ");
    if (scanf("%d", &taille) != 1 || taille <= 0)
    {
        fprintf(stderr, "Erreur : taille invalide.\n");
        return EXIT_FAILURE;
    }

    // =========================================================================
    // 2. ALLOCATION DYNAMIQUE SUR LE TAS (HEAP)
    // =========================================================================
    tableau = (int*) malloc((size_t)taille * sizeof(int));

    // TEST VITAL : Vérifier si malloc a échoué (saturation RAM)
    if (tableau == NULL)
    {
        fprintf(stderr, "Erreur critique : memoire RAM insuffisante !\n");
        return EXIT_FAILURE;
    }

    // =========================================================================
    // 3. REMPLISSAGE ET MANIPULATION
    // =========================================================================
    for (int i = 0; i < taille; ++i)
    {
        *(tableau + i) = (i + 1) * 10; // Arithmétique de pointeurs équivalente à tableau[i]
        somme += *(tableau + i);
    }

    printf("\nContenu du tableau dynamique alloue sur le tas :\n");
    for (int i = 0; i < taille; ++i)
    {
        printf("Element [%d] a l'adresse %p = %d\n", i, (void*)(tableau + i), tableau[i]);
    }

    printf("\nSomme totale calculee = %d\n", somme);

    // =========================================================================
    // 4. LIBÉRATION OBLIGATOIRE DE LA MÉMOIRE (VALGRIND 0 FUITE)
    // =========================================================================
    free(tableau);
    tableau = NULL; // Neutralisation du pointeur fantôme

    printf("Memoire du tas liberee avec succes. Fin du programme.\n");

    return EXIT_SUCCESS;
}

8. Auto-Évaluation Interactive : Pointeurs & Allocation (3 Questions)

Question 1 : Si ptr est un pointeur de type int* situé à l'adresse 0x2000, quelle est l'adresse de ptr + 2 sur une machine standard 64 bits ?

Explication : L'arithmétique des pointeurs avance par saut de taille d'élément. Pour un int de 4 octets, avancer de 2 éléments déplace le pointeur de 8 octets : $0x2000 + 8 = 0x2008$.
