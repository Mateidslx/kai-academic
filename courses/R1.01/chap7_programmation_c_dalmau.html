1. Le Rôle de la Programmation Machine à l'IUT d'Anglet

Après la conception formelle sur table avec M. Patrick Etcheverry (spécifications externes, dictionnaire des données, arbres de décomposition et schémas de flot de données), la mise en œuvre pratique en C / C++ est encadrée par M. Sébastien Dalmau.

En programmation système et en langage C (norme ANSI / ISO C99), la machine n'offre aucun filet de sécurité : il n'y a ni machine virtuelle, ni ramasse-miettes (garbage collector), ni vérification des débordements d'indices de tableaux. Le développeur pilote directement l'adressage mémoire physique et les registres du processeur.

2. Modèle Mémoire d'un Processus en Langage C

Lorsqu'un exécutable compilé est chargé en mémoire vive par le système d'exploitation (Linux), son espace d'adressage virtuel est partitionné en quatre segments distincts : 

+-------------------------------------------------------+ 0xFFFFFFFFFFFFFFFF (Adresses hautes)
| Segment du Noyau (Kernel Space) - inaccessible        |
+-------------------------------------------------------+
| LA PILE (Stack)                                       |
| - Variables locales automatiques                      |
| - Cadres d'appels de fonctions (Stack Frames)         |  | Croissance vers le bas
| - Adresses de retour                                  |  v (adresses décroissantes)
+ - - - - - - - - - - - - - - - - - - - - - - - - - - - +
|                   Zone Libre                          |
+ - - - - - - - - - - - - - - - - - - - - - - - - - - - +
| LE TAS (Heap)                                         |  ^ Croissance vers le haut
| - Allocations dynamiques (malloc, calloc, realloc)    |  | (adresses croissantes)
+-------------------------------------------------------+
| Segment de Données (BSS & Data)                       |
| - Variables globales et static initialisées ou non    |
+-------------------------------------------------------+
| Segment de Code (Text Segment)                        |
| - Instructions binaires machine en lecture seule      |
+-------------------------------------------------------+ 0x0000000000000000 (Adresses basses)
  • La Pile (Stack) : Mémoire ultra-rapide gérée automatiquement par le processeur (registres RSP / RBP). La portée d'une variable locale est strictement restreinte à son bloc { ... } ; sa mémoire est invalidée dès la sortie de la fonction.
  • Le Tas (Heap) : Espace de mémoire dynamique où le programmeur réserve manuellement des blocs au moment de l'exécution via malloc(). Les données persistent tant qu'elles ne sont pas explicitement libérées avec free().

4. Adresses Mémoire, Opérateurs de Pointeurs & Typage Fort

Un pointeur est une variable contenant l'adresse mémoire d'une autre variable en RAM.

  • Opérateur d'adresse & : Utilisé devant une variable, il retourne son adresse physique (ex. : &variable).
  • Opérateur de déréférencement * : Utilisé devant un pointeur, il accède directement au contenu stocké à l'adresse pointée (en lecture ou en écriture).
  • Le pointeur NULL : Adresse 0 servant de sentinelle pour indiquer l'absence de cible valide.
#include <stdio.h>

int main(void)
{
    int nombre = 42;
    int *pNombre = &nombre; // pNombre stocke l'adresse de la variable nombre

    printf("Valeur directe de nombre        : %d\n", nombre);
    printf("Adresse memoire de nombre (&n)  : %p\n", (void*)&nombre);
    printf("Valeur stockee dans pNombre     : %p\n", (void*)pNombre);
    printf("Valeur pointee (*pNombre)       : %d\n", *pNombre);

    // Modification indirecte de la valeur en memoire via le pointeur
    *pNombre = 99;
    printf("Apres *pNombre = 99, nombre vaut: %d\n", nombre);

    return 0;
}

5. Passage par Adresse aux Fonctions (Simulation de la Référence)

En langage C ANSI, tous les paramètres sont obligatoirement transmis par valeur (par copie). Pour qu'une fonction puisse modifier une variable appartenant à la fonction appelante, on lui transmet l'adresse de la variable : 

#include <stdio.h>

// Procedure formelle d'echange de deux entiers selon M. Dalmau
void echanger(int *a, int *b)
{
    // Garde defensive imperative
    if (a == NULL || b == NULL)
    {
        return;
    }
    int temporaire = *a;
    *a = *b;
    *b = temporaire;
}

int main(void)
{
    int x = 10;
    int y = 20;

    printf("Avant echange : x = %d, y = %d\n", x, y);
    echanger(&x, &y); // Transmission des adresses memoire avec l'operateur &
    printf("Apres echange : x = %d, y = %d\n", x, y);

    return 0;
}

6. Arithmétique des Pointeurs & Équivalence avec les Tableaux

En C, le nom d'un tableau se convertit implicitement en un pointeur constant vers son premier élément : tab == &tab[0].

Équivalence Fondamentale C : tab[i] <=> *(tab + i)

L'opération p + i incrémente l'adresse physique de i * sizeof(*p) octets : 

int tab[5] = {10, 20, 30, 40, 50};
int *p = tab; // p pointe sur tab[0]

// *(p + 2) accede a l'element a l'indice 2 (30)
// L'adresse memoire avance de 2 * sizeof(int) = 8 octets
printf("Element indice 2 : %d\n", *(p + 2));

7. Allocation Dynamique dans le Tas : malloc, calloc, realloc & free

Lorsque la dimension des données n'est pas connue à la compilation, on alloue dynamiquement la mémoire sur le tas via <stdlib.h> :

  • malloc(size_t tailleOctets) : Réserve un bloc de mémoire contigu sans initialiser son contenu (octets résiduels aléatoires).
  • calloc(size_t n, size_t tailleUnite) : Réserve la mémoire et initialise tous les octets à zéro.
  • realloc(void *ptr, size_t nouvelleTaille) : Redimensionne un bloc alloué tout en conservant son contenu.
  • free(void *ptr) : Restitue le bloc au système d'exploitation.
⚠️ RÈGLE DE SÉCURITÉ ABSOLUE :
L'appel à malloc() peut échouer si le système manque de RAM disponible. Il retourne alors NULL.
Tout appel à malloc DOIT être immédiatement suivi d'une vérification :
if (pointeur == NULL) { fprintf(stderr, "Erreur memoire\n"); exit(EXIT_FAILURE); }

8. Les 5 Pièges Mortels de la Mémoire en C

  1. 1. Segmentation Fault (Déréférencement de NULL ou hors-borne) :
    Tentative de lecture ou d'écriture à une adresse mémoire non allouée au processus (ex. : int *p = NULL; *p = 12;). Provoque le crash immédiat du programme (signal SIGSEGV).
  2. 2. Pointeur Sauvage (Wild Pointer) :
    Pointeur déclaré sans initialisation : int *p;. Sa valeur contient l'adresse poubelle qui traînait dans la pile. S'il est déréférencé, il écrase une zone mémoire arbitraire.
  3. 3. Pointeur Pendant (Dangling Pointer) :
    Pointeur qui continue de viser une adresse dont le bloc a déjà été libéré par free(). La parade consiste à toujours écrire : free(p); p = NULL;.
  4. 4. Double Libération (Double Free) :
    Appeler deux fois free() sur le même pointeur sans l'avoir remis à NULL entre-temps. Provoque la corruption de la table d'allocation du tas et une faille de sécurité critique.
  5. 5. Fuite Mémoire (Memory Leak) :
    Allouer de la mémoire avec malloc() puis perdre l'adresse du bloc sans avoir appelé free(). La mémoire reste consommée jusqu'à l'arrêt du programme, provoquant un épuisement de la RAM sur les serveurs ou daemons.

9. L'Audit Mémoire avec Valgrind (Exigence Stricte M. Dalmau)

À l'IUT d'Anglet, aucun code ne peut être validé sans avoir subi un audit dynamique rigoureux avec Valgrind.

Protocole Officiel de Compilation & Audit :

# 1. Compilation avec tous les avertissements actifs et symboles de débogage (-g)
gcc -Wall -Wextra -Werror -std=c99 -g tp_etudiant.c -o tp_etudiant

# 2. Exécution supervisée sous Valgrind avec traque complète des fuites
valgrind --leak-check=full --show-leak-kinds=all --track-origins=yes ./tp_etudiant

10. Programme Complet de Référence : Tableau Dynamique & Métrologie

#include <stdio.h>
#include <stdlib.h>

/**
 * Alloue dynamiquement un tableau de notes de taille n,
 * calcule la moyenne arithmetique et libere proprement toutes les ressources.
 */
int main(void)
{
    int nbNotes = 0;
    printf("Combien de notes souhaitez-vous saisir ? ");
    if (scanf("%d", &nbNotes) != 1 || nbNotes <= 0)
    {
        fprintf(stderr, "Erreur : Nombre de notes invalide.\n");
        return EXIT_FAILURE;
    }

    // Allocation dynamique dans le tas (Heap)
    double *notes = (double*)malloc((size_t)nbNotes * sizeof(double));
    if (notes == NULL)
    {
        fprintf(stderr, "Erreur critique : Echec de l'allocation memoire.\n");
        return EXIT_FAILURE;
    }

    // Saisie et initialisation des donnees
    for (int i = 0; i < nbNotes; i++)
    {
        notes[i] = 10.0 + (double)(i % 10);
    }

    // Calcul de la moyenne
    double somme = 0.0;
    for (int i = 0; i < nbNotes; i++)
    {
        somme += notes[i];
    }
    double moyenne = somme / nbNotes;
    printf("Moyenne des %d notes : %.2f / 20.0\n", nbNotes, moyenne);

    // LIBERATION OBLIGATOIRE DE LA MEMOIRE (Exigence stricte M. Dalmau)
    free(notes);
    notes = NULL; // Bonne pratique contre les dangling pointers

    return EXIT_SUCCESS;
}

QUESTION 1 / 4 R1.01 • Ch.7

Quelle est la conséquence critique de l'oubli de l'appel à « free(ptr); » après avoir utilisé de la mémoire allouée dynamiquement avec malloc ?

Explication Pédagogique : En C, il n'y a pas de ramasse-miettes (Garbage Collector). Tout ce qui est alloué avec malloc doit être libéré explicitement avec free. Les fuites de mémoire sont traquées et sanctionnées par les outils de vérification formelle (Valgrind) à l'IUT d'Anglet.
QUESTION 2 / 4 R1.01 • Ch.7

Quelle est la différence fondamentale entre la mémoire « Pile » (Stack) et la mémoire « Tas » (Heap) lors de l'exécution d'un programme C ?

Explication Pédagogique : Stack : gérée par le processeur via le registre SP (LIFO), ultra-rapide mais risque de Stack Overflow si trop de récursion. Heap : gérée par l'allocateur de l'OS (malloc/free), immense mais gestion manuelle de la durée de vie sous l'entière responsabilité du programmeur.
QUESTION 3 / 4 R1.01 • Ch.7

En langage C, comment s'effectue l'évaluation des expressions logiques utilisant les opérateurs && (ET) et || (OU) ?

Explication Pédagogique : Propriété vitale en C pour la sécurité mémoire : cela permet d'écrire sans risque 'if (ptr != NULL && *ptr == 42)'. Si ptr est NULL, le premier test est faux, donc *ptr n'est pas évalué et le programme évite un crash immédiat (Segmentation Fault) !
QUESTION 4 / 4 R1.01 • Ch.7

Que contiennent respectivement les opérateurs & et * en langage C appliqués à une variable ?

Explication Pédagogique : Règle de syntaxe fondamentale : si int a = 5; et int *p = &a; alors p contient l'adresse mémoire de a (ex: 0x7ffd80). L'expression *p évalue le contenu de la boîte pointée par p, c'est-à-dire 5. Modifier *p = 10 modifie directement la variable a !
