1. Modèle Conceptuel du Tableau (Vecteur)

Un tableau unidimensionnel est une collection ordonnée d'éléments de même type, stockés de manière contiguë en mémoire. Chaque élément est accessible en temps constant O(1) grâce à son indice (indexé de 0 à N-1 en C/C++).

// Déclaration statique en C :
int notes[100]; // 100 entiers consécutifs en mémoire
const unsigned int TAILLE_MAX = 100;
unsigned int nbElements = 0; // Taille logique réelle

2. Les Algorithmes Fondamentaux d'Etcheverry

Recherche Séquentielle (Drapeau)

Arrêt précoce dès que l'élément est trouvé, évitant de parcourir inutilement la fin du tableau.

bool trouve = false;
unsigned int i = 0;
while (i < nbElements && !trouve) {
    if (tab[i] == cible) trouve = true;
    else i++;
}
Recherche du Minimum avec Indice

Toujours initialiser l'indice minimum à 0 et comparer à partir du deuxième élément (indice 1).

unsigned int indMin = 0;
for (unsigned int i = 1; i < nbElements; i++) {
    if (tab[i] < tab[indMin]) indMin = i;
}
int valeurMin = tab[indMin];

QUESTION 1 / 4 R1.01 • Ch.8

Quand doit-on rigoureusement privilégier une boucle « for (int i = 0; i < N; i++) » par rapport à une boucle while selon les conventions de l'IUT d'Anglet ?

Explication Pédagogique : Règle de bonne pratique algorithmique d'Etcheverry & Dalmau : si on parcourt une structure de taille connue (comme un tableau de 0 à N-1) ou si l'on répète une action un nombre fixe de fois, on utilise 'for'. Si l'arrêt dépend d'un événement imprévisible (recherche réussie, saisie sentinelle), on utilise 'while'.
QUESTION 2 / 4 R1.01 • Ch.8

Quelle est la condition préalable indispensable pour pouvoir appliquer l'algorithme de Recherche Dichotomique (Binary Search) sur un tableau ?

Explication Pédagogique : La recherche dichotomique compare l'élément cherché à la valeur médiane. Si le tableau est trié, elle sait avec certitude dans quelle moitié chercher et élimine 50% des éléments restants à chaque étape (complexité en O(log N)). Sur un tableau non trié, elle est totalement inopérante et donne un résultat faux !
QUESTION 3 / 4 R1.01 • Ch.8

Pourquoi le Tri par Insertion (Insertion Sort) est-il particulièrement efficace sur un tableau « presque déjà trié » ?

Explication Pédagogique : Comme un joueur qui trie ses cartes dans sa main : il prend la carte suivante et l'insère à sa place ordonnée en décalant les précédentes. Si la carte est déjà plus grande que la précédente, zéro décalage ! C'est pourquoi les algorithmes hybrides modernes (comme Timsort dans Python/Java) utilisent le tri par insertion pour les petits sous-tableaux.
QUESTION 4 / 4 R1.01 • Ch.8

Quelle est la conséquence critique de l'oubli de l'appel à « free(ptr); » après avoir utilisé de la mémoire allouée dynamiquement avec malloc ?

Explication Pédagogique : En C, il n'y a pas de ramasse-miettes (Garbage Collector). Tout ce qui est alloué avec malloc doit être libéré explicitement avec free. Les fuites de mémoire sont traquées et sanctionnées par les outils de vérification formelle (Valgrind) à l'IUT d'Anglet.
