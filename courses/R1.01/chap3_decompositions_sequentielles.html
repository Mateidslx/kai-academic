1. La Décomposition Séquentielle : Ordre Chronologique & Dépendance de Données

La décomposition séquentielle est le mode d'organisation le plus élémentaire et fondamental en algorithmique. Elle stipule qu'une action complexe peut être réalisée en exécutant une suite de sous-actions ordonnées chronologiquement les unes après les autres.

RÈGLE FORMELLE DE LA SÉQUENCE (IUT D'ANGLET) :

Dans un arbre d'actions ou un schéma de conception formel (AlgoForge / Tabula Rasa), les sous-actions d'une séquence sont reliées par le symbole de séquence (noté avec deux barres parallèles ||) et s'exécutent strictement de gauche à droite. Une sous-action $A_{k+1}$ ne peut débuter tant que la sous-action précédente $A_k$ ne s'est pas intégralement achevée.

■ FORMALISME GRAPHIQUE DE LA SÉQUENCE DANS ALGOFORGE :

                         ┌─────────────────────────────┐
                         │    Action Globale Racine    │
                         └──────────────┬──────────────┘
                                        │
                                      [ || ]  (Symbole Séquence)
                                        │
                 ┌──────────────────────┼──────────────────────┐
                 ▼                      ▼                      ▼
       ┌───────────────────┐  ┌───────────────────┐  ┌───────────────────┐
       │   Sous-Action 1   │  │   Sous-Action 2   │  │   Sous-Action 3   │
       │   (Ex: Saisir)    │  │   (Ex: Calculer)  │  │   (Ex: Afficher)  │
       └───────────────────┘  └───────────────────┘  └───────────────────┘
          Ordre 1 (Début)       Ordre 2 (Milieu)        Ordre 3 (Fin)

Le Principe Sacré de la Dépendance de Données :

L'ordre de gauche à droite n'est jamais choisi au hasard : il est imposé par la circulation des informations. Une action $B$ qui a besoin d'une variable $X$ comme Donnée d'Entrée ne peut légitimement s'exécuter qu'après l'action $A$ qui a produit ou reçu cette variable $X$.

2. L'Arbre d'Actions Descendant (Top-Down Refinement)

La méthode d'Etcheverry repose sur le raffinement progressif (Top-Down Refinement, inspiré des travaux de Niklaus Wirth, créateur du Pascal). On part du problème général le plus abstrait (la racine de l'arbre), puis on le décompose par étapes successives jusqu'à n'obtenir que des actions élémentaires directement traduisibles en une seule instruction de code C++.

Action Composée (Nœud interne)

Action dont le niveau d'abstraction est trop élevé pour être programmée directement en une seule ligne de code. Elle nécessite d'être décomposée en sous-problèmes (séquentiels, alternatifs ou itératifs).

Ex: « Traiter la commande client » se décompose en « Vérifier stock », « Débiter compte » et « Générer facture ».

Action Élémentaire (Feuille de l'arbre)

Action minimale indivisible correspondant à une primitive du langage : une lecture clavier (cin >>), un affichage écran (cout <<) ou une affectation arithmétique simple (total = nb * tarif;).

Une fois toutes les feuilles atteintes, la conception est terminée !

3. Sémantique Formelle de l'Affectation & Modèle de Mémoire

L'affectation (notée ← en pseudo-code ou = en C++) est l'opération élémentaire la plus courante. Sa compréhension physique au niveau de la RAM est indispensable :

DÉROULEMENT INTERNE EN DEUX TEMPS STRICTS :

1. Évaluation : Le processeur évalue l'expression située à droite du signe d'affectation (calcul arithmétique, lecture d'autres variables).

2. Écriture destructrice : La valeur calculée est copiée dans la case mémoire associée à la variable de gauche. L'ancienne valeur préalablement stockée dans cette case est irrémédiablement écrasée et perdue.

⚠️ RUPTURE FONDAMENTALE AVEC LES MATHÉMATIQUES :

En mathématiques, l'écriture $x = x + 1$ est une aberration impossible (aucun nombre n'est égal à lui-même plus un). En informatique, x = x + 1; signifie : « Prendre la valeur actuelle stockée dans la case mémoire x, lui ajouter 1, puis ranger le nouveau résultat dans la case mémoire x ».

4. Le Casse-Tête Fondateur du SWAP (Échange de 2 Variables)

Supposons deux variables nb1 (contenant la valeur 5) et nb2 (contenant la valeur 9). On souhaite échanger leurs contenus pour que nb1 valle 9 et nb2 valle 5.

Démonstration de l'Erreur Classique de l'Étudiant Débutant :

Code Naïf Tenté :

1. nb1 = nb2;

2. nb2 = nb1;

Autopsie du Désastre en RAM :

À l'étape 1, nb1 prend la valeur 9. Mais ce faisant, son ancienne valeur (5) est écrasée et définitivement perdue !

À l'étape 2, nb2 reçoit la valeur actuelle de nb1 (9). Résultat : nb1 = 9 et nb2 = 9. L'échange a échoué lamentablement.

La Solution Mathématique Rigoureuse : La Variable Temporaire (temp)

Comme deux verres pleins dont on veut échanger les liquides (l'un d'eau, l'autre de vin), il est physiquement impossible de transvaser sans recourir à un troisième verre vide temporaire :

ALGORITHME CANONIQUE DU SWAP :

1. temp = nb1; // Étape 1 : Sauvegarder la valeur de nb1 dans le réservoir temporaire

2. nb1 = nb2; // Étape 2 : Écraser nb1 avec la valeur de nb2 (sécurisé car nb1 est sauvegardé)

3. nb2 = temp; // Étape 3 : Restituer la valeur initiale de nb1 dans nb2

Tableau de Trace Mémoire de l'Échange (Adresses et Cases RAM) :

Étape Instruction Exécutée Case RAM nb1 (0x1000) Case RAM nb2 (0x1004) Case RAM temp (0x1008) Commentaire Sémantique
Initial État de départ 5 9 Inconnu Données de départ
Étape 1 temp = nb1; 5 9 5 La valeur 5 est mise à l'abri dans temp
Étape 2 nb1 = nb2; 9 9 5 nb1 reçoit 9, son 5 est écrasé mais protégé en temp
Étape 3 nb2 = temp; 9 5 5 nb2 reçoit 5 depuis temp. Échange parfait !

5. Atelier Pièges d'Examen : Les Fautes Courantes en Séquence

PIÈGE SÉQUENTIEL Inversion de l'Ordre Séquentiel (Lire après avoir calculé) Éliminatoire

❌ Code Inversé

total = prix * 1.2;
cin >> prix;

⚠️ Diagnostic du Crash

La multiplication s'exécute alors que prix contient encore une valeur aléatoire poubelle non saisie. La saisie n'a lieu qu'ensuite, quand le total est déjà faux.

✅ Ordre Strict

cin >> prix;
total = prix * 1.2;

6. Exercice Guidé Intégral d'Amphi : La Décomposition Horaire

Énoncé : Écrire un algorithme complet qui lit un nombre total de secondes (ex: 7384 secondes) et calcule sa décomposition exacte en Heures, Minutes et Secondes restantes (ex: 2 heures, 3 minutes et 4 secondes).

Raisonnement Mathématique par Division Entière & Modulo :

• 1 minute = 60 secondes ; 1 heure = 3600 secondes.

• Nombre d'heures : division entière du total par 3600 : heures = totalSecondes / 3600 ($7384 / 3600 = 2$).

• Secondes restantes après extraction des heures : reste modulo 3600 : reste = totalSecondes % 3600 ($7384 \% 3600 = 184$).

• Nombre de minutes : division entière du reste par 60 : minutes = reste / 60 ($184 / 60 = 3$).

• Secondes finales restantes : reste modulo 60 : secondes = reste % 60 ($184 \% 60 = 4$).

Code C++ Conforme Style Allman :

/*
 * Programme : DecompositionHoraire
 * But : Convertir un temps total en secondes en heures, minutes et secondes.
 * Auteur : Matéi de Saint Leger
 */

#include <iostream>
using namespace std;

int main (void)
{
    // =========================================================================
    // CONSTANTES
    // =========================================================================
    const int SECONDES_PAR_HEURE = 3600;
    const int SECONDES_PAR_MINUTE = 60;

    // =========================================================================
    // VARIABLES
    // =========================================================================
    int totalSecondes; // Donnée d'entrée (Nature : D)
    int heures;        // Résultat heures (Nature : R)
    int minutes;       // Résultat minutes (Nature : R)
    int secondes;      // Résultat secondes (Nature : R)
    int resteSecondes; // Variable temporaire de calcul (Nature : INT)

    // =========================================================================
    // TRAITEMENTS SÉQUENTIELS (DE GAUCHE À DROITE)
    // =========================================================================
    // 1. Saisir le total de secondes
    cout << "Entrez le nombre total de secondes : ";
    cin >> totalSecondes;

    // 2. Extraire les heures et le reste
    heures = totalSecondes / SECONDES_PAR_HEURE;
    resteSecondes = totalSecondes % SECONDES_PAR_HEURE;

    // 3. Extraire les minutes et les secondes finales
    minutes = resteSecondes / SECONDES_PAR_MINUTE;
    secondes = resteSecondes % SECONDES_PAR_MINUTE;

    // 4. Afficher le résultat
    cout << totalSecondes << " s = " 
         << heures << " h " 
         << minutes << " min " 
         << secondes << " s." << endl;

    return 0;
}

7. Auto-Évaluation Interactive : Séquences & SWAP (3 Questions)

Question 1 : Si a = 3 et b = 8, quel est l'effet de la séquence : a = b; b = a; ?

Explication : Dès la première ligne a = b;, la variable a reçoit 8. Son ancienne valeur (3) est écrasée. La seconde ligne b = a; réaffecte donc 8 à b.
