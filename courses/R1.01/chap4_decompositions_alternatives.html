1. Fondements des Décompositions Alternatives : La Prise de Décision

Dans un programme purement séquentiel, chaque instruction est exécutée de manière rigide, indépendamment des valeurs saisies par l'utilisateur. Or, la quasi-totalité des problèmes réels exige que le comportement du programme s'adapte dynamiquement en fonction de la validité ou de l'état des données. C'est le rôle fondamental de la décomposition alternative.

LES DEUX LOIS CARDINALES DE L'ALTERNATIVE (PATRICK ETCHEVERRY) :

1. Principe d'Exclusion Mutuelle : Les branches d'une alternative sont strictement disjointes. Si la condition est VRAIE, la branche ALORS est exécutée et la branche SINON est ignorée. Si la condition est FAUSSE, la branche SINON est exécutée et la branche ALORS est ignorée. Il est physiquement impossible que les deux branches s'exécutent au cours d'une même évaluation.

2. Principe de Couverture Exhaustive : L'ensemble des branches doit couvrir 100% des cas possibles de l'univers des données. Aucune valeur permise par les préconditions $\{P\}$ ne doit être abandonnée sans traitement défini.

■ REPRÉSENTATION DANS ALGOFORGE & ORDINOGRAMME :

                            ┌────────────────────────┐
                            │ Condition Booléenne ?  │  (Hexagone / Losange)
                            └───────────┬────────────┘
                                        │
                         ┌──────────────┴──────────────┐
                   [ VRAI ]                        [ FAUX ]
                         │                              │
                         ▼                              ▼
              ┌─────────────────────┐        ┌─────────────────────┐
              │    Branche ALORS    │        │    Branche SINON    │
              │   (Action si Vrai)  │        │   (Action si Faux)  │
              └─────────────────────┘        └─────────────────────┘

2. Conditionnelle Simple : Quand a-t-on le Droit au « Sinon Vide » ?

Une question récurrente en TD : a-t-on le droit d'écrire un if sans clause else ? La réponse d'Etcheverry est nuancée et fait l'objet de points de barème aux contrôles :

Cas Légitime : Filtrage ou Mise à Jour d'Extremum

Lorsqu'on cherche le maximum ou qu'on applique une remise facultative, si la condition n'est pas remplie, il n'y a littéralement rien à faire : la variable conserve sa valeur précédente. 

if (nombre > maximumActuel)
{
    maximumActuel = nombre;
}
// Pas de else nécessaire ici !
Cas Interdit : Oubli de Gestion d'Erreur

Vérifier une entrée sans prévoir le cas erroné est sanctionné lourdement : le programme continue son exécution avec des données corrompues sans alerter l'utilisateur. 

// ❌ FAUTE D'EXAMEN :
if (note >= 0 && note <= 20)
{
    // Calcul...
}
// Manque le else : que fait-on si note = 999 ?

3. Évaluation en Court-Circuit (Short-Circuit Evaluation) en C++

Le standard ISO C++ applique une règle d'optimisation vitale pour la sécurité d'exécution des conditions logiques complexes :

LES DEUX RÈGLES DE COURT-CIRCUIT :

• Opérateur ET (&&) : Si l'opérande de gauche est FAUX, le résultat global est nécessairement faux. Le C++ n'évalue pas l'opérande de droite.

• Opérateur OU (||) : Si l'opérande de gauche est VRAI, le résultat global est nécessairement vrai. Le C++ n'évalue pas l'opérande de droite.

APPLICATION VITALE : PROTECTION CONTRE LA DIVISION PAR ZÉRO :

if (diviseur != 0 && (total / diviseur) > 10)
{
    cout << "Moyenne supérieure à 10";
}

Grâce au court-circuit, si diviseur == 0, le membre gauche est faux : le compilateur n'exécute JAMAIS total / diviseur, évitant ainsi le crash instantané du programme ! Si vous aviez inversé l'ordre : if ((total / diviseur) > 10 && diviseur != 0), le programme aurait planté !

4. L'Instruction de Choix Multiple : switch ... case ... break

Lorsqu'une variable entière ou caractère peut prendre une valeur parmi une liste discrète connue, l'enchaînement de nombreux if ... else if devient lourd et peu lisible. Le C++ propose l'instruction switch : 

switch (codeMenu)
{
    case 1:
        cout << "Option 1 : Consulter le profil" << endl;
        break; // INDISPENSABLE pour quitter le switch !

    case 2:
        cout << "Option 2 : Modifier les informations" << endl;
        break;

    case 3:
        cout << "Option 3 : Se déconnecter" << endl;
        break;

    default: // Capture tous les cas non prévus (OBLIGATOIRE EN PARTIEL)
        cout << "Erreur : Choix invalide !" << endl;
        break;
}

⚠️ LE DANGER MORTEL DU « FALLTHROUGH » (OUBLI DU break;) :

Si vous oubliez d'écrire break; à la fin d'un bloc case, le processeur ne s'arrête pas : il continue en « tombant » directement dans les instructions du case suivant, même si la condition ne correspond pas !

5. Atelier Pièges d'Examen : Les Fautes Courantes en Alternative

PIÈGE N°1 EN C++ Confondre Affectation (=) et Égalité (==) Crash Logique

❌ Code Erroné

if (role = 2)
{
cout << "Admin";
}

⚠️ Mécanisme Diabolique

L'instruction role = 2 n'est pas un test : c'est une affectation ! Elle écrase role avec la valeur 2. Or, en C++, toute valeur non nulle est considérée comme VRAIE. La condition est donc toujours VRAIE !

✅ Solution 20/20

if (role == 2)
{
cout << "Admin";
}

Toujours doubler le signe égal pour un test.

6. Exercice Guidé Intégral : Résolution Complète de $ax^2 + bx + c = 0$

Énoncé : Écrire un programme complet qui résout dans $\mathbb{R}$ l'équation quadratique $ax^2 + bx + c = 0$. Il doit couvrir exhaustivement l'intégralité des cas particuliers avec rigueur mathématique. 

/*
 * Programme : ResolutionSecondDegre
 * But : Calculer et afficher les solutions réelles de l'équation ax^2 + bx + c = 0.
 * Auteur : Matéi de Saint Leger
 */

#include <iostream>
#include <cmath> // Pour sqrt()
using namespace std;

int main (void)
{
    // =========================================================================
    // VARIABLES
    // =========================================================================
    double a, b, c;   // Coefficients réels (Nature : D)
    double delta;     // Discriminant b^2 - 4ac (Nature : INT)
    double x1, x2;    // Solutions calculées (Nature : R)

    // =========================================================================
    // TRAITEMENTS AVEC ALTERNATIVES IMBRIQUÉES
    // =========================================================================
    cout << "Entrez les coefficients a, b et c : ";
    cin >> a >> b >> c;

    // CAS DÉGÉNÉRÉ : a == 0 (Ce n'est pas du second degré mais du premier degré !)
    if (a == 0.0)
    {
        if (b == 0.0)
        {
            if (c == 0.0)
            {
                cout << "L'équation est vérifiée pour tout réel (Infinité de solutions)." << endl;
            }
            else
            {
                cout << "Équation impossible : aucune solution." << endl;
            }
        }
        else
        {
            x1 = -c / b;
            cout << "Équation du premier degré : solution unique x = " << x1 << endl;
        }
    }
    else // CAS RÉEL DU SECOND DEGRÉ (a != 0)
    {
        delta = (b * b) - (4.0 * a * c);

        if (delta > 0.0)
        {
            x1 = (-b - sqrt(delta)) / (2.0 * a);
            x2 = (-b + sqrt(delta)) / (2.0 * a);
            cout << "Deux solutions réelles distinctes : x1 = " << x1 
                 << " et x2 = " << x2 << endl;
        }
        else if (delta == 0.0)
        {
            x1 = -b / (2.0 * a);
            cout << "Une solution réelle double : x0 = " << x1 << endl;
        }
        else
        {
            cout << "Discriminant négatif (" << delta 
                 << ") : Aucune solution dans l'ensemble des réels R." << endl;
        }
    }

    return 0;
}

7. Auto-Évaluation Interactive : Alternatives (3 Questions)

Question 1 : Si x = 0, que produit l'expression if (x != 0 && 10 / x > 2) ?

Explication : En C++, l'opérateur && s'arrête immédiatement dès que son membre gauche est faux. Comme x != 0 est faux, 10 / x n'est jamais calculé.
