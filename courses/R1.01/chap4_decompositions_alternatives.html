1. Les Slides Officielles du Cours (03-alternative - 53 Diapos)

2. Principe & Formalisme de la Décomposition Alternative (Slide 4-10)

Une décomposition alternative exprime que la résolution d'un problème $P$ se fait selon la véracité d'une ou plusieurs conditions booléennes :

  • Sous le problème $P$, les sous-problèmes $P_1, P_2, \dots, P_n$ sont placés sur une même ligne horizontale.
  • Au-dessus de chaque branche, la condition d'activation est précisée entre crochets : $[C_1], [C_2], \dots, [C_n]$.

3. Les 4 Formes d'Alternatives (Slide 11-16)

  1. 1. Décomposition 'Si' (Action Conditionnelle Simple) :
    Le sous-problème n'est exécuté que si la condition est vraie. Sinon, on ne fait rien ($P ightarrow [C] ightarrow P_1$).
  2. 2. Décomposition 'Si - Sinon' (Alternative Binaire Exclusive) :
    Si la condition est vraie, on exécute $P_1$ ; sinon, on exécute obligatoirement $P_2$ ($[C] ightarrow P_1$ et $[ ext{non } C] ightarrow P_2$).
  3. 3. Décomposition 'Si - Si' (Conditions Indépendantes) :
    Deux conditions séparées. Attention : les deux actions peuvent être exécutées si les deux conditions sont satisfaites !
  4. 4. Décomposition 'Si - SinonSi - Sinon' (Cascade Exclusive) :
    Une suite de conditions ordonnées où seule la première condition vérifiée est exécutée.
  5. 5. Cas du 'Switch' (Aiguillage par Valeur, Slide 25-34) :
    Utilisé lorsque la résolution dépend de la valeur discrète d'une expression (ex. : valeur d'un dé entre 1 et 6).

4. La Règle d'Or Absolue : L'Exclusion Mutuelle des Conditions (Slide 22-23)

🚨 RÈGLE MAJEURE DE M. PATRICK ETCHEVERRY :

Le fait de rendre les conditions strictement mutuellement exclusives permet d'éviter des cas d'erreur, de rendre le programme indépendant de l'ordre d'évaluation des branches et d'assurer une robustesse totale.

Le Cas d'École des Mentions du Baccalauréat (Slide 21-23)

Considérons la moyenne d'un étudiant pour lui attribuer sa mention :

❌ MAUVAISE PRATIQUE (Sans exclusion)

if (moyenne >= 10) cout << "Passable";
if (moyenne >= 12) cout << "Assez Bien";
if (moyenne >= 14) cout << "Bien";
if (moyenne >= 16) cout << "Très Bien";
// Pour moyenne = 15, le programme
// affichera : "PassableAssez BienBien" !

✅ BONNE PRATIQUE (Exclusion mutuelle)

if (moyenne >= 16) {
    cout << "Très Bien";
} else if (moyenne >= 14) {
    cout << "Bien";
} else if (moyenne >= 12) {
    cout << "Assez Bien";
} else if (moyenne >= 10) {
    cout << "Passable";
}

5. Bonnes Pratiques de Codage C++ (Slide 38-41)

  • Placement systématique des accolades : Même pour une seule instruction, délimitez toujours les blocs par { } pour éviter le bug classique du dangling else.
  • Clause break dans le switch : Chaque clause case doit impérativement se terminer par break; pour éviter le fall-through accidentel.
  • Clause default obligatoire : Même si vous pensez avoir couvert tous les cas, prévoyez toujours un default défensif.
