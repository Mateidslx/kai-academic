Chapitre 3 : Bug Reports, Issue Tracking & Agile Scrum Ceremonies

Writing structured bug reports (steps to reproduce, expected vs actual behavior, severity), participating in daily standups and sprint retrospectives.

1. The Importance of Professional Technical Writing in Software Engineering

In an international development team or open-source community, clear and rigorous written English is essential. A poorly written bug report wastes hours of senior developer time, leads to misunderstandings, and causes delayed releases. Conversely, an actionable, well-documented bug report allows immediate reproduction and prompt patching.

2. Standard Anatomical Structure of a Professional Bug Report

Industry-standard issue trackers (GitHub Issues, Jira, Linear) follow a structured template that developers must master : 

### Title: [Component] Concise Summary of the Failure Behavior
*Example: [AuthModule] Segmentation fault when password string exceeds 256 characters*

### 1. Environment & Configuration
- **Operating System:** Ubuntu 22.04 LTS (x86_64) / Windows 11 WSL2
- **Compiler / Runtime:** GCC 11.4.0 with `-Wall -Wextra -Werror`
- **Application Version / Git Commit:** v1.2.0 (commit `a4f8b2c`)
- **Dependencies:** Valgrind 3.18.1, PostgreSQL 15.3

### 2. Preconditions
- The database contains at least one test user with role `STUDENT`.
- The user is logged out and on the landing login modal.

### 3. Steps to Reproduce (Deterministic Sequence)
1. Open terminal and run `./kai_academic_daemon --debug`.
2. Navigate to `http://localhost:8765/login.html`.
3. In the "Username" field, enter `matei.delestapis`.
4. In the "Password" field, paste a 512-character alphanumeric test string.
5. Click on the "Submit" button.

### 4. Expected Behavior
The application should validate input length, reject the payload cleanly with HTTP 422 Unprocessable Entity, and display a user-friendly error message: *"Password must not exceed 256 characters"*.

### 5. Actual Behavior
The daemon crashes abruptly with `SIGSEGV` (Segmentation fault). The stack trace reveals a buffer overflow in `auth_parser.c:142` inside the `strcpy()` call without boundary check.

### 6. Supporting Evidence & Valgrind Output
```text
==14298== Invalid write of size 1
==14298==    at 0x4842B80: strcpy (in /usr/libexec/valgrind/vgpreload_memcheck-amd64-linux.so)
==14298==    by 0x1092F4: parse_user_credentials (auth_parser.c:142)
==14298==  Address 0x4a580a0 is 0 bytes after a block of size 256 alloc'd
```

### 7. Severity & Priority
- **Severity:** High (Crash / Security vulnerability)
- **Priority:** P1 (Blocker for next milestone release)

3. Daily Scrum Stand-up Meeting in English

In Agile frameworks (Scrum, Kanban), team members participate in a daily 15-minute synchronization stand-up. Every developer answers 3 key questions using precise technical phrases :

  1. 1. What I accomplished yesterday :
    « Yesterday, I finalized the memory management refactoring in the C module, eliminated two memory leaks detected by Valgrind, and pushed my feature branch for peer review. »
  2. 2. What I plan to achieve today :
    « Today, I am going to write comprehensive unit test suites for the sorting algorithm benchmarks and document our API endpoints in the Markdown repository. »
  3. 3. Any impediments or blockers :
    « I am currently blocked by a schema mismatch on the PostgreSQL staging container. I need a quick 5-minute sync with the backend lead after the stand-up to align on foreign key constraints. »
