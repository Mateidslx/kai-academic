1. La Séparation Stricte Interface / Implémentation en C++ Moderne

Dans les projets d'ingénierie logicielle d'envergure, mélanger la déclaration des structures de données et leur code algorithmique dans un unique fichier est une erreur critique. En C++, la conception modulaire repose sur la séparation rigoureuse :

  • Le fichier d'en-tête (.hpp) : Définit le contrat public du module. Il contient la directive #pragma once pour empêcher les inclusions cycliques, les déclarations de constantes, les structures de données, et les prototypes formels des fonctions accompagnés de leur documentation Doxygen.
  • Le fichier source (.cpp) : Contient le corps exécutable des fonctions. Il inclut obligatoirement son propre en-tête et les bibliothèques système nécessaires.

2. Règles Fondamentales de Transmission des Paramètres

Pour garantir une efficacité maximale et éviter toute copie mémoire inutile, les étudiants doivent appliquer la règle d'or du passage de paramètres en C++ : 

#include <string>
#include <vector>
#include <iostream>

struct Client
{
    unsigned int id;
    std::string nom;
    double solde;
};

// 1. Types primitifs (int, double, char, bool) : passage par VALEUR
bool estSolvable(double montant, double soldeActuel)
{
    return soldeActuel >= montant;
}

// 2. Objets complexes (std::string, std::vector, structures) en LECTURE SEULE :
//    Passage obligatoire par RÉFÉRENCE CONSTANTE (const &) -> ZÉRO COPIE MÉMOIRE !
void afficherClients(const std::vector<Client>& liste)
{
    for (const auto& c : liste)
    {
        std::cout << "Client #" << c.id << " : " << c.nom << std::endl;
    }
}

// 3. Paramètres de sortie MODIFIÉS par la fonction :
//    Passage par RÉFÉRENCE NON CONSTANTE (&)
void crediterCompte(Client& clientCible, double montantAjout)
{
    if (montantAjout > 0.0)
    {
        clientCible.solde += montantAjout;
    }
}

3. Les Conteneurs de la Standard Template Library (STL)

En SAÉ 1.01, les tableaux statiques C bruts (int tab[100]) et les pointeurs nus non maîtrisés sont formellement proscrits. Les conteneurs dynamiques de la STL offrent robustesse et sécurité :

Conteneur STL Organisation Mémoire Complexité d'Accès Cas d'Usage Privilégié
std::vector<T> Tableau dynamique contigu en mémoire vive $\mathcal{O}(1)$ par index tab[i], $\mathcal{O}(1)$ amorti pour push_back Collection séquentielle par défaut, parcours rapide avec cache processeur.
std::string Chaîne dynamique de caractères gérée automatiquement $\mathcal{O}(1)$ par index, gestion automatique du caractère nul \0 Tous les traitements de texte et saisies utilisateurs.
std::map<K, V> Arbre binaire de recherche auto-équilibré (Rouge-Noir) $\mathcal{O}(\log n)$ en recherche, insertion et suppression Dictionnaires de données associant une clé unique à une entité.

4. Style de Programmation Allman & Rigueur Architecturale

Toutes les fonctions rédigées pour l'IUT d'Anglet adoptent la convention d'indentation Allman : chaque accolade ouvrante { et fermante } est placée seule sur sa propre ligne avec une indentation stricte de 4 espaces. Chaque fonction est découpée en 3 blocs visuels distincts : Déclaration des variables locales, Traitement algorithmique avec assertions défensives, et Retour du résultat.
