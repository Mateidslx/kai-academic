2. Modèle 1 : L'Échange de Deux Valeurs (Swap)

Problème : Permuter les valeurs contenues dans deux variables val1 et val2 de même type sans écraser ni perdre d'information.

Piège classique : Écrire val1 = val2; val2 = val1; écrase la valeur initiale de val1 dès la première ligne ! Il est indispensable de passer par une troisième variable temporaire nommée explicitement copieVal1 (ou copieValeur). 

// Modèle 1 : L'échange de deux valeurs
copieVal1 = val1;
val1 = val2;
val2 = copieVal1;

3. Modèle 2 : La Saisie-Vérification d'une Valeur

Problème : Demander une valeur à l'utilisateur et recommencer la saisie tant que la donnée fournie ne respecte pas les bornes ou conditions de validité attendues.

Pourquoi for ( ; ; ) + break ? Conformément à l'affiche méthodologique Concevoir des itérations (page Moodle #695682 et règle ES.77 des C++ Core Guidelines), le nombre de répétitions est inconnu a priori, il y a au moins une saisie à effectuer, et lorsqu'un message d'erreur doit être affiché avant de reboucler, la condition d'arrêt se situe au milieu du corps de la boucle. 

// Modèle 2 : La saisie-vérification d'une valeur (avec message d'erreur)
for ( ; ; )
{
    cout << "Entrez une note comprise entre " << NOTE_MIN << " et " << NOTE_MAX << " : ";
    cin >> noteSaisie;

    if ((noteSaisie >= NOTE_MIN) && (noteSaisie <= NOTE_MAX))
    {
        break;
    }

    cout << "Valeur incorrecte. Recommencez." << endl;
}

4. Modèle 3 : Le Parcours Complet avec Traitement Systématique (mainProf.cpp)

Définition officielle (Slide 17 de 07-modeles-algos-basiques) : Ce modèle consiste à balayer l'intégralité d'une structure à accès direct (tableau ou chaîne de caractères) du premier indice (0) au dernier indice (NB_CASES - 1) en appliquant un traitement à chaque élément sans exception (ex. affichage complet, saisie d'un tableau, somme/cumul pour calculer une moyenne).

Voici le fichier de référence exact mainProf.cpp extrait du dépôt patrick-etcheverry/code-explorer : 

/**
 * Fichier : mainProf.cpp (Référence officielle de M. Patrick Etcheverry - Dépôt code-explorer)
 * Modèle  : Le parcours complet avec traitement systématique
 */
#include <iostream>
using namespace std;

int main()
{
    // CONSTANTES
    const unsigned short int NB_NOTES = 10; // Nombre de notes composant le tableau

    // VARIABLES
    float notesControle1[NB_NOTES] = {15, 12.5, 8, 9, 4, 17, 5.5, 13, 11, 14}; // Notes obtenues au 1er contrôle
    float cumulNotes; // Cumul de toutes les notes du tableau notesControle1
    unsigned short int i; // Indice de parcours du tableau

    // TRAITEMENTS
    // Calcul de la somme des valeurs du tableau
    cumulNotes = 0.0;
    for (i = 0; i <= NB_NOTES - 1; i++)
    {
        cumulNotes = cumulNotes + notesControle1[i];
    }

    // Calcul et affichage de la moyenne
    cout << "Moyenne : " << cumulNotes / NB_NOTES << endl;

    return 0;
}

5. Modèle 4 : Le Parcours Complet avec Traitement Conditionné

Définition officielle (Slide 21 de 07-modeles-algos-basiques) : Comme pour le modèle précédent, on parcourt toutes les cases de la collection de 0 à NB_CASES - 1 (car plusieurs éléments peuvent nous intéresser), mais le traitement interne n'est déclenché que si l'élément courant vérifie une condition (structure if à l'intérieur de la boucle for).

Cas d'usage typiques dans les Katas :

  • Compter le nombre d'éléments vérifiant une propriété (ex. nombre de valeurs négatives, effectif d'un groupe de TP dans un tableau d'étudiants).
  • Rechercher le minimum ou le maximum d'un tableau (initialiser valMax = tab[0] puis parcourir de 1 à NB_CASES - 1 avec if (tab[i] > valMax)).
  • Afficher ou modifier uniquement les éléments qui respectent un critère (ex. toutes les positions d'une voyelle dans un mot).

6. Modèle 5 : La Recherche de Première Occurrence

Définition officielle (Slides 25 à 38 de 07-modeles-algos-basiques) : Lorsqu'on cherche si un élément particulier (ou un contre-exemple) existe dans une collection, il est formellement interdit d'utiliser une boucle for qui continuerait à tourner après avoir trouvé l'élément ! Le parcours est partiel et gouverné par une boucle while ((!trouve) && (posCourante < NB_CASES)).

📐 LES 4 ÉTAPES OBLIGATOIRES DU MODÈLE DE RECHERCHE DE 1RE OCCURRENCE :
  1. Initialiser la recherche : trouve = false; et posCourante = 0; (ou NB_CASES - 1 si recherche de dernière occurrence en partant de la fin !).
  2. Effectuer la recherche : Boucle while ((!trouve) && (posCourante < NB_CASES)) avec une alternative if (conditionCible) { trouve = true; } else { posCourante = posCourante + 1; }.
  3. Ne jamais incrémenter posCourante dans la branche if (trouve = true), afin que posCourante conserve exactement l'indice de l'élément trouvé à la sortie de la boucle !
  4. Déterminer le résultat après la boucle : Tester if (trouve) pour exploiter posCourante, sinon afficher que l'élément est absent.

QUESTION 1 / 3 S1.01 • Choix du Modèle

On vous demande d'afficher la position de la DERNIÈRE voyelle d'une chaîne de caractères (Exercice 7b du TD7). Quel modèle d'algorithme permet de résoudre ce problème de la façon la plus efficace ?

Explication Pédagogique (M. Patrick Etcheverry) : Chercher la dernière occurrence en partant de la gauche obligerait à parcourir toute la chaîne. En adaptant la Recherche de première occurrence à rebours (depuis l'indice taille - 1 vers 0), la première voyelle rencontrée est immédiatement la dernière voyelle du mot !
