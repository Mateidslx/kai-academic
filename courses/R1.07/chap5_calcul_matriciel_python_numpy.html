1. Pourquoi Utiliser NumPy pour le Calcul Matriciel en BUT ?

En Python standard, manipuler des matrices avec des listes imbriquées ([[1, 2], [3, 4]]) pose deux problèmes majeurs :

  • Inefficacité algorithmique : Les boucles imbriquées for en Python pur sont lentes car exécutées par l'interpréteur CPython.
  • Surconsommation mémoire : Chaque élément d'une liste Python standard est un objet enveloppé (boxed object) avec un surcoût d'au moins 28 octets.

La bibliothèque NumPy résout cela en allouant des blocs contigus de mémoire en langage C (ndarray) et en exécutant des routines compilées ultra-optimisées (BLAS / LAPACK) exploitant les registres vectoriels SIMD des processeurs modernes.

3. Piège Fondamental : Produit de Hadamard vs Produit Matriciel

🚨 ERREUR COMMISE PAR 80% DES ÉTUDIANTS EN TP :
En Python NumPy, l'opérateur * effectue la multiplication élément par élément (Produit de Hadamard) !
Pour effectuer le véritable produit matriciel mathématique $C = A imes B$, il faut impérativement utiliser l'opérateur @ ou la fonction np.matmul(A, B). 
# Produit élément par élément (Hadamard) : [A]_ij * [A]_ij
produit_terme_a_terme = A * A

# Véritable produit matriciel C_ij = sum_k (A_ik * A_kj)
produit_matriciel = A @ A  # ou np.matmul(A, A) ou np.dot(A, A)
print("Résultat du vrai produit matriciel A @ A :
", produit_matriciel)

4. Module numpy.linalg : Déterminant, Inverse et Résolution de Systèmes

Le sous-module numpy.linalg regroupe les fonctions de base de l'algèbre linéaire numérique : 

# 1. Calcul du déterminant
det_A = np.linalg.det(A)
print(f"Déterminant numérique : {det_A:.4f}")

if not np.isclose(det_A, 0.0):
    # 2. Inversion de matrice
    A_inv = np.linalg.inv(A)
    print("Matrice inverse A^-1 :
", A_inv)
    
    # Vérification formelle : A @ A^-1 doit être égal à la matrice identité I_3
    identite_obtenue = A @ A_inv
    print("Est proche de l'identité ?", np.allclose(identite_obtenue, np.eye(3)))
    
    # 3. Résolution de système linéaire A @ X = B
    # RÈGLE D'OR : Toujours utiliser solve(A, B) plutôt que inv(A) @ B !
    # solve() utilise la décomposition LU de Gauss, 3x plus rapide et beaucoup plus stable.
    X = np.linalg.solve(A, B)
    print("Solution exacte X du système :", X)
else:
    print("Matrice singulière : impossible d'inverser.")

QUESTION 2 / 4 R1.07 • Ch.5

Dans la résolution d'un système linéaire AX = B, quand dit-on que le système est « incompatible » (ou impossible) ?

Explication Pédagogique : Une équation 0 = b (avec b non nul, ex: 0 = 5) est une contradiction mathématique insoluble. L'ensemble des solutions est alors l'ensemble vide S = ∅. Cela arrive lorsque le rang de la matrice des coefficients est inférieur au rang de la matrice augmentée.
QUESTION 3 / 4 R1.07 • Ch.5

En algèbre matricielle, existe-t-il des « diviseurs de zéro » (peut-on avoir A * B = 0 avec A ≠ 0 et B ≠ 0) ?

Explication Pédagogique : Exemple célèbre vu en TD : A = [[0, 1], [0, 0]] et B = [[1, 0], [0, 0]]. A ≠ 0 et B ≠ 0, pourtant A * B = [[0, 0], [0, 0]] ! On ne peut donc PAS simplifier par A dans une équation AC = AB même si A ≠ 0 (il faut que A soit inversible).
QUESTION 4 / 4 R1.07 • Ch.5

Pourquoi la stratégie du « pivot partiel » (choisir pour pivot le coefficient de valeur absolue maximale sur la colonne) est-elle recommandée en calcul numérique sur ordinateur ?

Explication Pédagogique : En virgule flottante (IEEE 754), diviser par un pivot minuscule (ex: 10^-15) amplifie de façon exponentielle les erreurs d'arrondi sur les autres coefficients. Le pivot partiel stabilise l'algorithme.
