Sécurité Web Front-End : Attaques XSS, CSRF, CSP & Bonnes Pratiques

Enseignant Référent : Mme Sophie Voisin / M. Roegel — IUT de Bayonne et du Pays Basque (Campus d'Anglet)

Mécanismes des failles XSS (stockée, réfléchie, DOM), assainissement des entrées, protection CSRF avec SameSite et tokens, et en-têtes Content Security Policy.

1. La Vulnérabilité XSS (Cross-Site Scripting)

Une faille XSS se produit lorsqu'une application injecte des données fournies par l'utilisateur directement dans la page sans échappement ni assainissement. Le navigateur de la victime interprète alors ces données comme du code JavaScript exécutable.

  • XSS Stockée (Stored) : Le script malveillant est enregistré dans la base de données (ex: commentaire de forum) et exécuté par tous les utilisateurs qui consultent la page. C'est la forme la plus critique.
  • XSS Réfléchie (Reflected) : Le script est injecté via l'URL (ex: paramètre de recherche ?q=<script>...</script>) et renvoyé immédiatement par le serveur.
  • DOM-based XSS : La faille réside purement dans le code JavaScript côté client qui manipule dangereusement les API du DOM (ex: location.search passé à eval() ou innerHTML).
🚨 RÈGLE D'OR FRONT-END ABSOLUE :
Bannir impérativement l'affectation directe de données externes via element.innerHTML = donneeExterne; !
Utiliser systématiquement element.textContent = donneeExterne; (qui encode automatiquement tous les caractères spéciaux en texte brut inoffensif) ou assainir la chaîne avec une bibliothèque auditée comme DOMPurify.

2. Attaques CSRF (Cross-Site Request Forgery)

Dans une attaque CSRF, un site pirate force le navigateur de la victime authentifiée à envoyer une requête HTTP vers une application cible où elle possède une session active (ex: virement bancaire, suppression de compte).

Les Parades Indispensables :

  1. Attribut de Cookie SameSite=Strict ou SameSite=Lax : Empêche le navigateur de joindre le cookie d'authentification lors de requêtes initiées depuis un domaine tiers.
  2. Jeton Anti-CSRF (CSRF Token) : Jeton cryptographique imprévisible généré par le serveur, stocké en session et injecté dans chaque formulaire HTML modifiant (<input type="hidden" name="csrf_token" value="...">).

3. Content Security Policy (CSP) : La Ligne Maginot du Front-End

L'en-tête HTTP Content-Security-Policy indique au navigateur quelles sources de scripts, de styles, d'images et de connexions sont autorisées à s'exécuter sur la page : 

Content-Security-Policy: default-src 'self'; script-src 'self' https://cdn.jsdelivr.net; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; object-src 'none'; base-uri 'self';
  • default-src 'self' : Par défaut, seules les ressources issues de la même origine sont autorisées.
  • object-src 'none' : Bloque l'exécution de plugins archaïques et dangereux (Flash, Java Applets).
  • base-uri 'self' : Empêche la modification de la balise <base> pour rediriger les chemins relatifs.

4 Questions
QUESTION 1 / 4 R1.02 • Ch.5

Pourquoi doit-on impérativement privilégier « element.textContent » plutôt que « element.innerHTML » pour insérer du texte provenant d'un utilisateur ?

QUESTION 2 / 4 R1.02 • Ch.5

Que signifie le fait que le protocole HTTP soit fondamentalement « sans état » (Stateless) ?

Explication Pédagogique : Par conception originelle (Tim Berners-Lee), HTTP ne mémorise rien entre deux échanges. Pour gérer des sessions utilisateurs (paniers d'achat, authentification connectée), le web a dû inventer des mécanismes complémentaires : les Cookies HTTP, les sessions côté serveur et les tokens JWT.
QUESTION 3 / 4 R1.02 • Ch.5

De l'intérieur vers l'extérieur, dans quel ordre exact s'organisent les composants du Modèle de Boîte (Box Model) CSS ?

Explication Pédagogique : Cœur absolu du rendu CSS : 1. Content (la zone de texte/image), 2. Padding (l'espace interne entourant le contenu, coloré avec le fond de l'élément), 3. Border (la bordure visible ou invisible), 4. Margin (l'espace externe transparent repoussant les éléments voisins).
QUESTION 4 / 4 R1.02 • Ch.5

Pourquoi la règle universelle « * { box-sizing: border-box; } » est-elle systématiquement appliquée dans les feuilles de style professionnelles modernes ?

Explication Pédagogique : Par défaut (content-box), un élément de width: 200px auquel on ajoute padding: 20px et border: 2px mesure en réalité 244px de large ! Avec 'box-sizing: border-box', la boîte mesure exactement 200px au total, le padding et la bordure étant absorbés à l'intérieur.
