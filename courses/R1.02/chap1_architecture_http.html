1. Le Modèle d'Architecture Client-Serveur du Web

Le World Wide Web repose sur un modèle d'échange asymétrique entre un client (navigateur Web comme Firefox ou Chrome) et un serveur HTTP (Apache, Nginx, Caddy). Le protocole HTTP (HyperText Transfer Protocol) est un protocole de la couche application de la pile Internet (au-dessus de TCP/TLS ou UDP/QUIC), historiquement sans état (stateless).

Chaque requête émise par le client est autonome et contient toutes les métadonnées nécessaires à son traitement par le serveur, sans que celui-ci ne conserve d'état implicite entre deux requêtes sans mécanisme explicite (cookies, tokens JWT).

2. Évolution du Protocole : HTTP/1.1, HTTP/2 et HTTP/3

Version Protocole Sous-Jacent Format des Trames Multiplexage Compression Headers
HTTP/1.1 (RFC 2616) TCP pur (+ TLS) Texte ASCII lisible Non (Head-of-Line Blocking) Aucune
HTTP/2 (RFC 7540) TCP unique (+ TLS) Binaire en trames (Frames) Oui (flux virtuels simultanés) HPACK
HTTP/3 (RFC 9114) QUIC (sur UDP) Binaire multiplexé natif Oui (zéro HoL blocking même en perte de paquet) QPACK

Méthode Rôle Sémantique Sûre (Safe) ? Idempotente ? Corps (Body) autorisé ?

5. Les Grandes Familles de Codes de Statut HTTP

  • 1xx (Informationnel) : 101 Switching Protocols (passage à WebSocket).
  • 2xx (Succès) :
    • 200 OK : Requête traitée avec succès.
    • 201 Created : Ressource créée (suite à un POST). Header Location: /ressources/42 retourné.
    • 204 No Content : Action exécutée avec succès mais aucun corps à renvoyer (ex: DELETE).
  • 3xx (Redirection) :
    • 301 Moved Permanently : Redirection définitive mise en cache par les navigateurs.
    • 302 Found : Redirection temporaire.
    • 304 Not Modified : Ressource inchangée par rapport au cache client (en-têtes If-None-Match / If-Modified-Since).
  • 4xx (Erreur Client) :
    • 400 Bad Request : Syntaxe invalide ou payload JSON malformé.
    • 401 Unauthorized : Authentification requise (en-tête WWW-Authenticate).
    • 403 Forbidden : Authentifié mais droits d'accès insuffisants.
    • 404 Not Found : Ressource introuvable à cette URI.
    • 405 Method Not Allowed : Méthode non supportée sur cette route (ex: POST sur route en lecture seule).
    • 429 Too Many Requests : Dépassement de quota de débit (Rate Limiting).
  • 5xx (Erreur Serveur) :
    • 500 Internal Server Error : Exception non rattrapée côté backend.
    • 502 Bad Gateway : Erreur de communication entre proxy inverse (Nginx) et serveur applicatif (Node/Gunicorn).
    • 503 Service Unavailable : Surcharge momentanée ou maintenance planifiée.
    • 504 Gateway Timeout : Le serveur applicatif en amont a mis trop de temps à répondre.

6. En-têtes HTTP Fondamentaux & Sécurité Moderne

  • Content-Type : Indique le type MIME (ex: application/json; charset=utf-8, text/html).
  • Authorization : Contient le jeton porteur (Bearer eyJhbGci...).
  • Cache-Control : Directives de mise en cache (no-cache, max-age=3600, immutable).
  • Strict-Transport-Security (HSTS) : Force le navigateur à communiquer exclusivement en HTTPS.
  • Access-Control-Allow-Origin (CORS) : Déclare les origines autorisées à consommer l'API via XMLHttpRequest/Fetch.

QCM Interactif d'Auto-Évaluation (Format Partiel Sans Par Cœur)

Conçu pour réviser efficacement entre deux cours : 4 propositions par question avec justification détaillée immédiate.

4 Questions
QUESTION 1 / 4 R1.02 • Ch.1

Quelle est la différence sémantique fondamentale entre les méthodes HTTP GET et POST ?

Explication Pédagogique : Règle universelle de l'architecture REST : GET doit être idempotent (l'exécuter 10 fois a exactement le même résultat que l'exécuter 1 fois) et sûr. POST modifie l'état côté serveur et ne doit jamais être utilisé pour une simple consultation de page.
QUESTION 2 / 4 R1.02 • Ch.1

À quelle catégorie appartiennent respectivement les codes de statut HTTP 200, 301, 404 et 500 ?

Explication Pédagogique : Standard HTTP : 1xx Information, 2xx Succès, 3xx Redirection (ex: 301 Moved Permanently), 4xx Erreurs imputables au Client (ex: 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found), 5xx Erreurs imputables au Serveur (ex: 500 Internal Server Error, 502 Bad Gateway).
QUESTION 3 / 4 R1.02 • Ch.1

Que signifie le fait que le protocole HTTP soit fondamentalement « sans état » (Stateless) ?

Explication Pédagogique : Par conception originelle (Tim Berners-Lee), HTTP ne mémorise rien entre deux échanges. Pour gérer des sessions utilisateurs (paniers d'achat, authentification connectée), le web a dû inventer des mécanismes complémentaires : les Cookies HTTP, les sessions côté serveur et les tokens JWT.
QUESTION 4 / 4 R1.02 • Ch.1

Comment l'API Fetch gère-t-elle une réponse d'erreur HTTP provenant du serveur, comme un code 404 (Not Found) ou 500 (Server Error) ?

Explication Pédagogique : Piège universel de l'API Fetch : une Promesse fetch() n'est rejetée (.catch()) qu'en cas de panne réseau matérielle ou de problème DNS. Si le serveur répond avec un code 404 ou 500, la communication a bien eu lieu, donc la promesse est résolue ! Il faut toujours vérifier 'if (!response.ok) throw new Error(...)'.
