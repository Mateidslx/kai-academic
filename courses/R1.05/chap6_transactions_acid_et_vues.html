Chapitre 6 : Gestion des Transactions ACID, Verrous & Création de Vues

Propriétés ACID (Atomicité, Cohérence, Isolation, Durabilité), commandes transactionnelles (COMMIT, ROLLBACK, SAVEPOINT), gestion de la concurrence et verrous, vues logiques (CREATE VIEW).

1. Les 4 Propriétés ACID d'une Transaction

Une transaction est une suite d'opérations SQL exécutées comme une unité de travail logique indivisible. Pour garantir l'intégrité de la base de données, tout SGBD transactionnel doit respecter les 4 propriétés fondamentales ACID :

A - Atomicité (All or Nothing)

La transaction s'exécute entièrement ou pas du tout. Si une panne ou une erreur survient au milieu, toutes les modifications déjà effectuées sont annulées (ROLLBACK).

C - Cohérence (Consistency)

La transaction fait passer la base d'un état valide à un autre état valide, en respectant scrupuleusement toutes les contraintes d'intégrité (CHECK, clés étrangères, unicité).

I - Isolation

Deux transactions exécutées simultanément ne doivent pas interférer. Les modifications d'une transaction en cours restent invisibles aux autres transactions tant qu'elle n'est pas validée.

D - Durabilité

Dès qu'une transaction est validée (COMMIT), ses effets sont gravés de manière définitive sur disque (via le journal des transactions WAL) et survivront à tout crash serveur ou coupure de courant.

-- Exemple de virement bancaire sécurisé
BEGIN TRANSACTION;

UPDATE COMPTE SET solde = solde - 200.00 WHERE numCompte = 1001;
UPDATE COMPTE SET solde = solde + 200.00 WHERE numCompte = 2002;

-- Si les deux updates réussissent sans violation de contrainte (ex: solde >= 0)
COMMIT;
-- En cas d'erreur
-- ROLLBACK;

2. Les Vues SQL (CREATE VIEW) & Intérêts de Sécurité

Une vue est une table virtuelle dont le contenu est défini dynamiquement par le résultat d'une requête SELECT mémorisée dans le catalogue du SGBD.

  • Simplification des Requêtes : Permet d'encapsuler des jointures complexes de 5 tables dans un objet simple réutilisable.
  • Sécurité & Confidentialité des Données : Permet de donner accès à un utilisateur à certaines colonnes ou certaines lignes sans lui donner accès à la table sous-jacente (ex: masquer le salaire ou le numéro de sécurité sociale).
  • Indépendance Logique : Si le schéma physique change, on peut réécrire la vue pour que les applications clientes continuent de fonctionner sans modifier leur code source.
-- Création d'une vue sécurisée pour l'administration des notes
CREATE OR REPLACE VIEW V_MOYENNES_ETUDIANTS AS
SELECT e.numEtudiant, e.nom, e.prenom, p.libelle AS promotion,
       ROUND(AVG(n.note), 2) AS moyenne_generale,
       COUNT(n.codeModule) AS nb_epreuves_passees
FROM ETUDIANT e
JOIN PROMOTION p ON e.idPromo = p.idPromo
LEFT JOIN NOTER n ON e.numEtudiant = n.numEtudiant
GROUP BY e.numEtudiant, e.nom, e.prenom, p.libelle;

-- Interrogation immédiate de la vue comme une table normale
SELECT * FROM V_MOYENNES_ETUDIANTS WHERE moyenne_generale >= 10.0;
