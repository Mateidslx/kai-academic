1. Les Propriétés ACID des Transactions

Une transaction est une unité logique de traitement composée d'une suite d'opérations SQL qui doivent s'exécuter de manière atomique.

Propriété Signification Sémantique Mécanisme SGBD
A - Atomicité Tout ou rien. Si une opération échoue au milieu, la transaction est intégralement annulée. Journal des transactions (Redo/Undo logs), commande ROLLBACK.
C - Cohérence La transaction fait passer la base d'un état intègre à un autre état intègre, en respectant toutes les contraintes. Validation des clés primaires, étrangères et des contraintes CHECK.
I - Isolation Deux transactions exécutées simultanément ne doivent pas produire d'interférences (lecture sale, lecture non répétable). Verrous (locks) et niveaux d'isolation (Read Committed, Serializable).
D - Durabilité Dès que la transaction est validée (COMMIT), ses effets sont persistants et garantis contre toute panne matérielle. Écriture synchrone des journaux sur disque non-volatile.

3. Vues Relationnelles (CREATE VIEW)

Une vue est une table virtuelle définie par une requête SQL stockée. Elle ne stocke aucune donnée elle-même, mais calcule dynamiquement ses lignes à chaque consultation. 

-- Création d'une vue sécurisée masquant les données confidentielles
CREATE OR REPLACE VIEW VueEtudiantsReussite AS
SELECT e.idEtudiant, e.nom, e.prenom, g.codeGroupe,
       ROUND(AVG(n.valeurNote), 2) AS moyenne
FROM Etudiant e
JOIN GroupeTD g ON e.idGroupe = g.idGroupe
JOIN Note n ON e.idEtudiant = n.idEtudiant
GROUP BY e.idEtudiant, e.nom, e.prenom, g.codeGroupe
HAVING AVG(n.valeurNote) >= 10.0;

QUESTION 2 / 4 R1.05 • Ch.6

Que retourne une jointure externe gauche (LEFT OUTER JOIN) entre deux tables A et B ?

Explication Pédagogique : LEFT JOIN préserve l'intégralité des lignes de la table de gauche (A). Si une ligne de A n'a pas de correspondance dans B, les colonnes de B sont remplies avec NULL (très utile pour trouver les clients sans commande par exemple).
QUESTION 3 / 4 R1.05 • Ch.6

Quelle est la règle formelle d'intégrité d'une entité dans un MCD selon M. Marquesuzaà ?

Explication Pédagogique : Chaque occurrence de l'entité doit pouvoir être identifiée sans ambiguïté par son identifiant (clé primaire conceptuelle). Les propriétés multivaluées (ex: plusieurs numéros de téléphone dans un même champ) sont strictement proscrites en Merise.
QUESTION 4 / 4 R1.05 • Ch.6

Comment dérive-t-on une association ternaire (reliant 3 entités A, B, C avec des cardinalités maximales à n) ?

Explication Pédagogique : Toute association n-aire (de dimension >= 3) se traduit systématiquement par une relation (table) associative. Sa clé primaire est composée de la concaténation des identifiants des entités participantes, complétée par les éventuels attributs portés par l'association.
