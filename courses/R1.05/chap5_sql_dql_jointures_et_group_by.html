Chapitre 5 : SQL DQL Avancé : Jointures, Agrégats, GROUP BY & Sous-Requêtes

Extraction de données complexes : jointures internes (INNER JOIN), jointures externes (LEFT/RIGHT JOIN), fonctions d'agrégation (COUNT, SUM, AVG, MIN, MAX), groupement avec GROUP BY et HAVING, sous-requêtes corrélées (EXISTS).

1. L'Ordre d'Évaluation Logique d'une Requête SQL

Le SGBD n'exécute pas une requête SQL dans l'ordre où elle est écrite ! Comprendre l'ordre logique d'exécution est indispensable pour écrire des requêtes complexes sans erreur :

Ordre d'écriture :

SELECT > FROM > JOIN > WHERE > GROUP BY > HAVING > ORDER BY > LIMIT

Ordre logique d'évaluation interne par le SGBD :

  1. FROM & JOIN : Construction du produit cartésien et application des jointures.
  2. WHERE : Filtrage ligne à ligne selon les prédicats de base (avant tout regroupement).
  3. GROUP BY : Partitionnement des lignes restantes en sous-groupes selon les attributs de groupement.
  4. HAVING : Filtrage des groupes selon des conditions sur fonctions d'agrégation.
  5. SELECT : Projection des colonnes demandées et calcul des expressions.
  6. DISTINCT : Élimination des doublons de lignes dans le résultat.
  7. ORDER BY : Tri final des résultats (utilise les alias du SELECT).
  8. LIMIT / OFFSET : Pagination et restriction du nombre de lignes retournées.

2. Maîtrise Complète des Jointures Internes & Externes

Type de Jointure Syntaxe SQL Standard Comportement & Lignes Retenues
INNER JOIN (Jointure Interne) FROM T1 INNER JOIN T2 ON T1.id = T2.id_t1 Ne retient que les lignes ayant une correspondance stricte dans les deux tables. Les lignes orphelines sont ignorées.
LEFT OUTER JOIN (Jointure Gauche) FROM T1 LEFT JOIN T2 ON T1.id = T2.id_t1 Conserve toutes les lignes de la table de gauche (T1). Si aucune correspondance n'existe dans T2, les colonnes de T2 sont remplies de NULL.
RIGHT OUTER JOIN (Jointure Droite) FROM T1 RIGHT JOIN T2 ON T1.id = T2.id_t1 Symétrique : conserve toutes les lignes de la table de droite (T2), complétées par des NULL si pas de T1.
FULL OUTER JOIN (Jointure Totale) FROM T1 FULL JOIN T2 ON T1.id = T2.id_t1 Conserve toutes les lignes des deux tables, avec des NULL de part et d'autre en l'absence de correspondance.

Exemple classique de partiel : Trouver les clients qui n'ont JAMAIS commandé

SELECT c.numClient, c.nomClient, c.prenomClient
FROM CLIENT c
LEFT JOIN COMMANDE cmd ON c.numClient = cmd.numClient
WHERE cmd.numCommande IS NULL;

3. La Règle d'Or du GROUP BY et HAVING

🚨 LA RÈGLE D'OR ABSOLUE DU GROUP BY :

Dès qu'une requête comporte une clause GROUP BY, TOUT attribut présent dans la clause SELECT qui n'est pas enveloppé dans une fonction d'agrégation (COUNT, SUM, AVG, MIN, MAX) DOIT OBLIGATOIREMENT FIGURER DANS LA CLAUSE GROUP BY !
Toute violation de cette règle provoque une erreur SQL immédiate du SGBD (ERROR: column must appear in the GROUP BY clause).

Différence Fondamentale entre WHERE et HAVING :

WHERE (Filtre Ligne)

S'applique avant le regroupement, ligne par ligne. Ne peut JAMAIS contenir de fonction d'agrégation (ex: WHERE AVG(note) >= 10 est une aberration syntaxique !).

HAVING (Filtre Groupe)

S'applique après le regroupement sur les groupes calculés. S'utilise exclusivement pour filtrer sur le résultat d'agrégats (ex: HAVING AVG(note) >= 10.0).

-- Lister les promotions ayant au moins 15 étudiants avec une moyenne générale supérieure à 12
SELECT p.libelle, COUNT(e.numEtudiant) AS nb_etudiants, ROUND(AVG(n.note), 2) AS moyenne_promo
FROM PROMOTION p
JOIN ETUDIANT e ON p.idPromo = e.idPromo
JOIN NOTER n ON e.numEtudiant = n.numEtudiant
GROUP BY p.idPromo, p.libelle
HAVING COUNT(DISTINCT e.numEtudiant) >= 15
   AND AVG(n.note) >= 12.0
ORDER BY moyenne_promo DESC;
