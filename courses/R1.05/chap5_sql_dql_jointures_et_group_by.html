Interrogation DQL : Jointures, GROUP BY & Sous-Requêtes

Enseignant Référent : M. Christophe Marquesuzaà / M. Yon Dourisboure — IUT de Bayonne et du Pays Basque (Campus d'Anglet)

Syntaxe SELECT exhaustive, jointures internes et externes (LEFT/RIGHT JOIN), fonctions d'agrégation, clauses GROUP BY et HAVING, sous-requêtes corrélées et analyse des erreurs de partiel.

1. L'Ordre d'Évaluation Sémantique d'une Requête SQL

Pour ne jamais se tromper dans la rédaction d'une requête, il faut connaître l'ordre dans lequel le moteur SQL évalue les clauses :

  1. FROM & JOIN : Construction du produit cartésien et filtrage des jointures.
  2. WHERE : Filtrage ligne par ligne (tuples individuels). Les fonctions d'agrégat y sont interdites !
  3. GROUP BY : Partitionnement des tuples en groupes disjoints.
  4. HAVING : Filtrage global appliqué aux groupes après agrégation.
  5. SELECT : Projection des colonnes et calcul des expressions demandées.
  6. ORDER BY : Tri final des résultats projetés.

2. Les Différents Types de Jointures

  • Jointure Interne (INNER JOIN) : Ne conserve que les couples de lignes vérifiant la condition de jointure. Si un étudiant n'a pas de note, il n'apparaît pas. 
    SELECT e.nom, e.prenom, n.valeurNote
FROM Etudiant e
INNER JOIN Note n ON e.idEtudiant = n.idEtudiant;
  • Jointure Externe Gauche (LEFT OUTER JOIN) : Conserve toutes les lignes de la table de gauche (ici Etudiant), même si elles n'ont aucune correspondance à droite (les colonnes de droite sont alors remplies de NULL). 
    -- Affiche TOUS les étudiants, y compris ceux qui n'ont AUCUNE note
SELECT e.nom, e.prenom, NVL(TO_CHAR(n.valeurNote), 'Non noté') AS note
FROM Etudiant e
LEFT JOIN Note n ON e.idEtudiant = n.idEtudiant;

3. Agrégation : La Règle d'Or du GROUP BY

RÈGLE D'OR DE MARQUESUZAÀ :
Dès qu'une requête comporte une clause GROUP BY, TOUTE colonne mentionnée dans le SELECT qui n'est pas emballée dans une fonction d'agrégation (COUNT, SUM, AVG, MIN, MAX) DOIT OBLIGATOIREMENT figurer dans la liste du GROUP BY ! 
-- Moyenne des notes par groupe TD pour les groupes ayant une moyenne >= 10
SELECT g.codeGroupe, 
       COUNT(DISTINCT e.idEtudiant) AS nbEtudiants,
       ROUND(AVG(n.valeurNote), 2) AS moyenneGroupe
FROM GroupeTD g
JOIN Etudiant e ON g.idGroupe = e.idGroupe
JOIN Note n ON e.idEtudiant = n.idEtudiant
GROUP BY g.idGroupe, g.codeGroupe
HAVING AVG(n.valeurNote) >= 10.0
ORDER BY moyenneGroupe DESC;

4. Analyse des Pièges et Erreurs Fréquentes aux Examens de R1.05

❌ Piège 1 : Mettre une fonction d'agrégation dans le WHERE
SELECT nom FROM Note WHERE AVG(valeurNote) > 10; -- ERREUR SQL ORA-00934: group function is not allowed here
Correction : Utiliser la clause HAVING AVG(valeurNote) > 10 après un GROUP BY.
❌ Piège 2 : Confondre COUNT(*) et COUNT(colonne)
COUNT(*) compte le nombre total de lignes (même si des colonnes valent NULL).
COUNT(colonne) ne compte que les lignes où colonne IS NOT NULL !
❌ Piège 3 : Les comparaisons avec la valeur NULL
En SQL, colonne = NULL ne renvoie JAMAIS vrai car NULL représente l'inconnu ! Il faut obligatoirement écrire colonne IS NULL ou colonne IS NOT NULL.
