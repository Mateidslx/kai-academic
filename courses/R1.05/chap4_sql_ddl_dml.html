Chapitre 4 : SQL DDL & DML : Création de Tables, Contraintes & Manipulation

Création rigoureuse de tables avec contraintes déclaratives : PRIMARY KEY, FOREIGN KEY avec ON DELETE CASCADE, CHECK, UNIQUE, NOT NULL. Insertion, mise à jour et suppression (INSERT, UPDATE, DELETE).

1. Le Langage SQL DDL (Data Definition Language)

Le LDD (Langage de Définition de Données) permet de créer, modifier et supprimer les objets d'une base de données relationnelle sous un SGBD (PostgreSQL, Oracle, MySQL).

SYNTAXE FORMELLE DE CREATE TABLE AVEC CONTRAINTES NOMMÉES :

M. Marquesuzaà exige que toutes les contraintes soient explicitement nommées avec le mot-clé CONSTRAINT selon la nomenclature officielle :
• pk_nomtable pour la clé primaire.
• fk_nomtable_tablecible pour la clé étrangère.
• ck_nomtable_nomattribut pour les contraintes de domaine CHECK.
• uq_nomtable_nomattribut pour l'unicité UNIQUE. 

-- Ordre de suppression inverse des dépendances (pour éviter les erreurs de clés étrangères)
DROP TABLE IF EXISTS NOTER CASCADE;
DROP TABLE IF EXISTS ETUDIANT CASCADE;
DROP TABLE IF EXISTS PROMOTION CASCADE;

-- 1. Table parente PROMOTION
CREATE TABLE PROMOTION (
    idPromo       INT GENERATED ALWAYS AS IDENTITY,
    libelle       VARCHAR(50) NOT NULL,
    anneeScolaire CHAR(9) NOT NULL,
    CONSTRAINT pk_promotion PRIMARY KEY (idPromo),
    CONSTRAINT uq_promotion_libelle UNIQUE (libelle),
    CONSTRAINT ck_promotion_annee CHECK (anneeScolaire LIKE '____-____')
);

-- 2. Table fille ETUDIANT
CREATE TABLE ETUDIANT (
    numEtudiant   INT GENERATED ALWAYS AS IDENTITY,
    nom           VARCHAR(50) NOT NULL,
    prenom        VARCHAR(50) NOT NULL,
    email         VARCHAR(120) NOT NULL,
    dateNaissance DATE NOT NULL,
    idPromo       INT NOT NULL,
    CONSTRAINT pk_etudiant PRIMARY KEY (numEtudiant),
    CONSTRAINT uq_etudiant_email UNIQUE (email),
    CONSTRAINT ck_etudiant_email CHECK (email LIKE '%@%.%'),
    CONSTRAINT ck_etudiant_naissance CHECK (dateNaissance < CURRENT_DATE),
    CONSTRAINT fk_etudiant_promotion FOREIGN KEY (idPromo)
        REFERENCES PROMOTION(idPromo)
        ON DELETE RESTRICT
        ON UPDATE CASCADE
);

2. Le Langage SQL DML (Data Manipulation Language)

Le LMD permet de manipuler les données contenues dans les relations : insertion, mise à jour et suppression.

1. INSERT INTO

Insère un ou plusieurs n-uplets :

INSERT INTO PROMOTION (libelle, anneeScolaire)
VALUES ('BUT1-INFO-G1', '2026-2027');

2. UPDATE ... SET

Modifie des n-uplets existants :

UPDATE ETUDIANT
SET email = 'matei.new@univ-pau.fr'
WHERE numEtudiant = 42;

3. DELETE FROM

Supprime des n-uplets selon prédicat :

DELETE FROM ETUDIANT
WHERE numEtudiant = 42;

🚨 LE PIÈGE MORTEL DE L'OUBLI DE LA CLAUSE WHERE :

Exécuter DELETE FROM ETUDIANT; ou UPDATE ETUDIANT SET idPromo = 1; sans clause WHERE affecte l'intégralité des enregistrements de la table ! En production d'entreprise, cette erreur entraîne une perte massive de données irrécupérable sans restauration de sauvegarde.
