Chapitre 2 : Dérivation Rigoureuse du MCD vers le MLD Relationnel

Les 4 règles formelles de passage : entités en tables relationnelles, migration de clé étrangère (#) pour les associations (x,1)-(x,n), table d'association avec clé composite pour (x,n)-(x,n), et cardinalités (0,1)-(1,1).

1. Les Fondements du Modèle Relationnel d'Edgar F. Codd (1970)

Inventé par Edgar F. Codd chez IBM en 1970, le modèle relationnel repose sur la théorie mathématique des relations et de la théorie des ensembles. Une base de données relationnelle est un ensemble de relations (terme mathématique pour désigner les tables).

Vocabulaire Théorique (Codd) :
  • • Relation : Ensemble de n-uplets (tuples).
  • • Tuple (ou n-uplet) : Une ligne dans une table (occurrence).
  • • Attribut : Une colonne (propriété élémentaire).
  • • Domaine : L'ensemble des valeurs admissibles pour un attribut.
  • • Degré : Nombre d'attributs de la relation.
  • • Cardinalité : Nombre de tuples dans la relation à l'instant $t$.
Vocabulaire Usuel SGBD / SQL :
  • • Table : Représentation visuelle d'une relation.
  • • Ligne (Enregistrement) : Un n-uplet de données.
  • • Colonne (Champ) : Un attribut typé.
  • • Clé Primaire (Primary Key) : Attribut ou groupe d'attributs minimal identifiant chaque ligne.
  • • Clé Étrangère (Foreign Key) : Attribut faisant référence à la clé primaire d'une autre table.

2. Les 4 Règles Formelles de Dérivation MCD -> MLD

Le passage du MCD au MLD relationnel est un processus algorithmique strict ne laissant place à aucune interprétation subjective :

RÈGLE 1 : TRADUCTION DES ENTITÉS

Toute entité du MCD devient une relation (table) dans le MLD.
• Son identifiant devient la clé primaire de la relation (soulignée en continu).
• Ses autres propriétés deviennent les attributs (colonnes) de la table.

ETUDIANT (numEtudiant, nom, prenom, email, dateNaissance)

RÈGLE 2 : ASSOCIATION BINAIRE DE TYPE (x,1) - (x,n) [1 à n]

Pour toute association binaire reliant une entité à cardinalité maximale 1 (côté 0,1 ou 1,1) à une entité à cardinalité maximale n (côté 0,n ou 1,n) :
• La clé primaire de l'entité côté $(x,n)$ migre dans la table côté $(x,1)$ en tant que clé étrangère (notée avec un # ou soulignée en pointillés).
• Si l'association possédait des attributs propres, ils migrent également dans la table côté $(x,1)$.

PROMOTION (idPromo, libelle, anneeScolaire)

ETUDIANT (numEtudiant, nom, prenom, #idPromo)

RÈGLE 3 : ASSOCIATION (x,n) - (x,n) [Plusieurs à Plusieurs] & ASSOCIATIONS N-AIRES

Toute association binaire $(x,n) \leftrightarrow (x,n)$ ou toute association de dimension $\ge 3$ (ternaire, ...) devient une nouvelle relation (table d'association) :
• Sa clé primaire est la concaténation composite des identifiants de toutes les entités connectées.
• Chacun de ces attributs est simultanément une clé étrangère faisant référence à sa table respective.
• Les attributs propres de l'association deviennent les colonnes normales de cette nouvelle table.

ETUDIANT (numEtudiant, nom, prenom)

MATIERE (codeMatiere, intitule, creditsECTS)

NOTER (#numEtudiant, #codeMatiere, note, dateEvaluation)

RÈGLE 4 : CAS PARTICULIER DES ASSOCIATIONS (0,1) - (1,1)

La clé de l'entité côté (0,1) migre dans la table côté (1,1) avec une contrainte d'unicité (UNIQUE), OU inversement selon la logique métier prédominante (privilégier l'entité qui a le cycle de vie le plus dépendant pour éviter les valeurs nulles).

3. Intégrité Référentielle & Politiques ON DELETE

L'intégrité référentielle garantit qu'une clé étrangère ne peut jamais pointer vers un enregistrement parent qui n'existe pas. Que se passe-t-il lors de la suppression d'un enregistrement parent ?

Clause SQL Comportement du SGBD Cas d'Usage Recommandé
ON DELETE RESTRICT (ou NO ACTION) Le SGBD bloque et refuse la suppression du parent s'il existe au moins une ligne enfant dépendante. Comportement par défaut le plus sécuritaire (ex : interdire de supprimer un client s'il a des factures enregistrées).
ON DELETE CASCADE La suppression de la ligne parente entraîne automatiquement la suppression en cascade de toutes les lignes filles. Lignes filles n'ayant aucun sens sans le parent (ex : supprimer une commande supprime automatiquement ses lignes d'articles).
ON DELETE SET NULL La clé étrangère dans la table fille est positionnée à NULL (requiert que la colonne accepte les nulls). Optionnel : un salarié dont le département est supprimé passe temporairement en statut « non affecté ».

4. Exercice Type d'Examen Résolu : Dérivation MLD Complète

Reprenons le cas de la Clinique Vétérinaire du Chapitre 1 pour appliquer rigoureusement les 4 règles de dérivation vers le MLD textuel formel.

// --- MODÈLE LOGIQUE DE DONNÉES (MLD) OFFICIEL ---

CLIENT (numClient, nomClient, prenomClient, telephone, email)

VETERINAIRE (matriculeVet, nomVet, specialite)

ANIMAL (numPuce, nomAnimal, espece, race, dateNaissance, #numClient)

CONSULTATION (numConsultation, dateHeureConsult, diagnostic, tarifFacture, #numPuce, #matriculeVet)

MEDICAMENT (codeCIP, denomination, prixUnitaire)

PRESCRIRE (#numConsultation, #codeCIP, posologie)

Analyse des dérivations :

  • ANIMAL hérite de #numClient car l'association POSSEDER a pour cardinalité (1,1) côté animal et (1,n) côté client (Règle 2).
  • CONSULTATION hérite à la fois de #numPuce (concerne 1 animal) et de #matriculeVet (effectuée par 1 vétérinaire) (Règle 2 appliquée deux fois).
  • PRESCRIRE est une association (0,n)-(0,n) : elle devient une table propre dont la clé primaire composite est (numConsultation, codeCIP) et porte l'attribut posologie (Règle 3).
